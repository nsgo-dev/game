### Security

- `pkg/ktx2`: a KTX2 file of a few kilobytes from a mod, pack or model can no longer make the decoder allocate gigabytes. `Decode` refuses a Zstandard or ZLIB texture whose levels inflate to more than 256 MiB in total from its header, before decompressing anything, and decompresses each level into one buffer allocated once; decoding a level to RGBA (`DecodeRGBA`, `Texture.DecodeLevelRGBA`, and `Texture.Transcode` to another format, which `render3d.LoadKTX2` uses for its CPU fallback and for UASTC and BasisLZ/ETC1S textures) refuses a level larger than 8192x8192, whose RGBA image would exceed 256 MiB, and `Transcode` to another format refuses output totalling more than 256 MiB; `DecodeRGBA` decompresses only the level it returns; and `LoadKTX2` no longer copies levels it uploads in their own format. Block-compressed and universal textures up to 8192x8192 with their mip chains still load in a block format as before. A full 16384x16384 BC7 or UASTC mip chain no longer loads, a larger block-compressed texture still uploads in its own format on a device that supports it, a UASTC or BasisLZ/ETC1S texture larger than 8192x8192 no longer loads, and a CPU fallback to RGBA8 is limited to 256 MiB of output, so a full 8192x8192 mip chain on a device without its block format no longer loads; update to this release if your game loads KTX2 files it did not build itself (GHSA-9mh9-5gjq-r7h8).

### Fixed

- `pkg/ktx2`: binary key/value values the KTX2 specification defines, such as `KTXdxgiFormat__` and `KTXglFormat`, are written without a terminator and read back byte for byte, and a string value loses only its one terminating NUL, where `DecodeKVD` used to strip every trailing zero byte (GHSA-9mh9-5gjq-r7h8).
