### Security

- `game/online/netplay`: `LockstepSession` and `RollbackSession` keep their per-tick state bounded whatever a match member sends (GHSA-wwhg-x33m-mf5r). A lockstep session ignores a member's checksum for a tick more than 256 ticks behind or ahead of its own, and a rollback session one for a tick older than its checksum history, and prunes remote checksums by their own ticks. A `RollbackSession` no longer runs more than `MaxRollback` ticks past the oldest tick still waiting for a remote peer's input: `Step` then simulates nothing and returns the new `ErrRollbackStalled`, which matches `ErrRollbackWindowExceeded` with `errors.Is`, until the input arrives or the host removes the peer, so a peer that stops sending stalls the match instead of growing snapshots and inputs every tick. The stall error names each peer the session waits for, and the new `RollbackSession.Waiting` returns their IDs; since a stalled session sends such a peer nothing more, it is never reported with `ErrSessionBacklog`, and the host removes a peer that keeps the match stalled. A stalled `Step` returns a pending `ErrSessionBacklog` on its own rather than joined with the stall. Callers that return every `Step` error should skip `ErrRollbackStalled` and keep calling `Step` each frame. A rollback session now takes a peer's checksum only for its checksum ticks, and both sessions keep only the latest 256 events for `Desyncs()`, while `OnDesync` and `Stats().Desyncs` still see every one.
