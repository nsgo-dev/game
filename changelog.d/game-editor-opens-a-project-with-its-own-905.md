### Added

- `game/project`: `Resolver` (`NewResolver`) loads what a scene names from a project's own files: sprite atlases found by name nearest the scene as `game check` finds them (`NearestAtlases`, `ForScene`), with their images read from the project, scene files, whose atlas names it resolves from each file's own directory so an instanced or inherited scene in another directory draws the atlas `game check` finds for it, materials, physics materials, and through `ReadFile` the YAML tilesets and Tiled and LDtk maps tilemaps name; it lists the project's atlases (`AtlasNames`) and reads them and its materials again after `Refresh`, and is safe for concurrent use. `AtlasNamed`, `SkipDir`, `IsAtlasJSON`, `ResolveRef` and `HasScheme` are the atlas and path rules it shares with `game check`, so an atlas `meta.image` such as `hero 1:2.png` that `game check` accepts draws in the editor too (#905).
- `game/editor`: `Editor.ProjectAssets` makes opening a project switch the editor's resolver to a `project.Resolver` over it, so its scenes draw its own atlases, the asset browser lists them and its scene files place as instances; `OpenProjectScene` opens a project with another of its scenes, setting `ScenePath` so an instance of the open scene in itself is refused as a cycle (#905).
- `game/editor/editorcmd`: the scene editor's command line, shared by `nsgo game editor` and a game's own editor command: `New`, `Open`, `Run`, `Main`, `Show`, `Serve`, which serves the editor's MCP endpoint in a game's own editor too, and `ProjectRoot`, with `Options.RequirePlugins` refusing a project that lists a plugin the command lacks and `Options.WindowWidth` and `Options.WindowHeight` sizing the window (default 1120 by 680). An editor built with `Options.Components` checks scenes against those types together with the built-in physics components, so a scene with a `body2d` still opens in a game's own editor (#905).
- `game generate editor` writes a game's own editor command, a `main` built with the `gameeditor` tag that checks the project's scenes against its `Components` and builds in its editor plugins, and tags every file that declares the game's `main`, for any platform, `!gameeditor`; it refuses such a file when it also declares something the rest of the package needs, such as a name another file uses or an `init` function, which the editor build would lose (#905).

### Changed

- `game editor` opens a project, or a scene file inside one, with the project's own atlases, scene files and free-form components in place of the demo room's atlases and component registry, and runs the project's own editor command when it has one, written by `game generate editor` or as a `cmd/editor` main package that imports `editorcmd`, which takes the same command line; a `cmd/editor` that does not is reported and not run. Field Medic's `cmd/editor` now runs on `editorcmd.Main`, so it opens a scene file and a clip as `game editor` does, still in a 1280 by 800 window (#905).
- `game/editor`: without a component registry, `SetComponentField` still checks the fields of the built-in physics components (`sceneformat.PhysicsComponentRegistry`) as the inspector shows them, while a game's own components stay free-form, so a project opened with free-form components refuses a misspelled `body2d` field, as the demo registry did (#905).
