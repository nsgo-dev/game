### Security

- `online/accounts`, `online/cloudsave`, `online/leaderboard/selfhost`, `cmd/cloudsaved`, `cmd/leaderboardd`: each consumer of account tokens now accepts only tokens issued for its own audience, so the token a player sends a game server no longer works on the cloud save service, the self-hosted leaderboard or the account service's `GET /v1/me` and `POST /v1/link/*` (GHSA-8w88-jhc8-w88x). Sign-in tokens stay game server tokens; a device gets a token for another service with `POST /v1/refresh {"session", "audience"}` (`Service.RefreshFor`), where `audience` is `accounts` for the account service itself or an entry of the new `audiences` list in `accounts.yaml` (`DefaultConfig` lists `cloudsave` and `leaderboard`). `cloudsave.yaml` and `leaderboards.yaml` gain an optional `audience` (`cloudsave` and `leaderboard` by default), `cloudsave.New` and `selfhost.New` refuse a verifier for any other audience (build it with the new `token.NewVerifierFor`), and the daemons refuse to start when their audience is the key set's. To upgrade, add `audiences: [cloudsave, leaderboard]` to `accounts.yaml`, have clients request a token per service, and build service verifiers with `token.NewVerifierFor`.
