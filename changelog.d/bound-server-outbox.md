### Security

- `game/pkg/online/netplay`: `WebSocketServer.Send` and `WebTransportServer.Send` no longer write to a client's connection on the caller's goroutine, so a client that stops reading can no longer stall the match's tick, and every other client, for the 10-second write timeout. Each client now has a bounded outbox (`OutboxLimits`, 256 frames and 4 MiB by default) written by its own goroutine: past it the client's oldest unreliable frames are dropped, and a reliable frame that does not fit ends the client's session with `PeerLeft` and the reason `"outbox full"`. `WebTransportServer` queues each client's unreliable datagrams the same way, so a client that stops acknowledging QUIC packets cannot hold `Send` in QUIC's datagram queue; oversized datagrams still return `ErrPayloadTooLarge` at once. A write that fails or times out now closes the connection instead of leaving a partial frame that misframed every later one. Because `Send` returns before anything is written, it reports only `ErrDisconnected`, `ErrUnknownPeer`, `ErrPayloadTooLarge` and `ErrClosed`: a write that fails later shows up as `PeerDropped` from `NextEvent`, not as an error from `Send`. `WebSocketServer.Kick` and `Close` flush the frames already queued for a client before the close frame, for at most a second, and no longer write to the connection on the caller's goroutine. `SetOutboxLimits` and `OutboxStats` (`OutboxReporter`) tune and report the outboxes; a game that sends large reliable bursts should raise the limits rather than remove them (GHSA-gw6m-3wq3-4782).
