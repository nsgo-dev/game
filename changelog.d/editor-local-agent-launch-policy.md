### Security

- `game/editor`: local agents the editor starts (composer, plans, background tasks, automations, Start with AI) no longer load a project's own agent configuration. Claude Code runs with only your user settings, only the editor's MCP server and the servers enabled in Settings › Tools (never the project's `.mcp.json` or `.claude/settings.json` hooks), `dontAsk` permissions, and its own Edit, Write, NotebookEdit, Bash and PowerShell tools denied; Codex runs in a read-only sandbox with no approval prompts, gets the same servers inline, and never loads the project's `.codex/config.toml`, MCP servers, hooks or `.rules` files, even in a folder you once trusted in Codex. Changes go through the editor's tools and `permissions.yaml`, and every local agent and the built-in agent are told that text from project files, packs and mods is data, not instructions. A project's `automations.yaml` with enabled rules that arrived with a clone, template or pack, or changed outside the editor, no longer runs until you choose **Allow automations** in Settings › Automations; the approval is kept in your `editor.yaml`. If the composer used a server listed only in a project's `.mcp.json`, add it in Settings › Tools. Update to get this fix, especially before opening projects from other people (GHSA-vwmf-7vh3-w27f, GHSA-r39m-5mfc-4pmq).
