# 格斗游戏模板

`fighting2d` 是一个一对一的 2D 格斗游戏，可作为格斗游戏的起点：两名原创角色，搓招触发的必杀技，取消与连段，上下段防御，三局两胜且有计时的回合，电脑对手，以及第二名玩家，可以和第一名玩家共用一个键盘、用第二个手柄，对战电脑时还可以用触屏。它主要基于识别输入的 [fighting](fighting.md) 和结算命中的 [framedata](framedata.md)，并用到 [input](input.md)、[sound](sound.md)、[screen](screen.md) 和[占位资源包](placeholder.md)的音效。

```sh
go run github.com/nsgo-dev/game/cmd/game@latest new -template fighting2d myfighter
cd myfighter
go tool nsgo dev
```

`nsgo init -template github.com/nsgo-dev/game/template/fighting2d` 会写出同样的项目（见[项目模板](templates.md)）。

## 它展示了什么

- **搓招与连段。** 每名角色的招式集（`data/<fighter>.moves.yaml`）是一个 `fighting.MoveSet`：Kestrel 的 gale 是前四分之一圆，talon 是升龙拳指令，Basalt 的 ram 是先蓄后再前，两人都有双击方向的冲刺或后撤步。每名玩家有一个 `fighting.Recognizer`，每一步读取输入，并随角色转身镜像；其中的连段为打中的招式串命名。
- **帧数据既是玩法也是画面。** 每个招式的受击框、攻击框、伤害、受击硬直、防御硬直、击退和取消窗口都是一个 `framedata.Doc`（`data/<fighter>.frames.yaml`），由 `framedata.World` 逐步推进并找出命中。角色就是用这些框画出来的，第一个受击框画成头部，所以看到的就是能打中和能被打中的范围；调试构建中按 F1 会直接显示这些框。
- **防御。** 对手在攻击范围内出招或飞行道具逼近时按住后方即可防御，按住后下方则蹲防。下段必须蹲防，中段（跳跃攻击）必须站防，被防住的必杀技仍会造成削血伤害。
- **回合。** 一回合在击倒对手或 60 秒计时结束时结束，计时结束时剩余体力比例高的一方获胜，所以体力上限更高的角色不会因此占便宜。双方同时被击倒，或计时结束时剩余比例相同，算作平局，平局回合双方各记一胜：先赢两回合者赢下比赛，所以一方已赢一回合后再打平，比赛由这一方获胜；平局让双方同时达到两胜时，整场比赛为平局。命中停顿、连段伤害衰减和墙角推开都是 `data/match.yaml` 中的规则。
- **电脑对手。** 它每隔几步根据距离、对手的攻击和跳跃做出决定，并像玩家一样把决定变成输入，经过同一个识别器和同样的规则，按每名角色的输入脚本出招；随机源带种子，所以同一场比赛能原样重放。
- **本地双人。** 两名玩家的按键、手柄按钮和摇杆都在 `game.yaml` 的同一份输入映射里，动作名以 `p1_` 和 `p2_` 开头。每名玩家有自己的 `input.Actions`；接上两个手柄时，第一个给玩家 1，第二个给玩家 2。触屏为玩家 1 提供屏幕摇杆和两个攻击按钮，按钮区域同样写在 `game.yaml` 里。
- **会玩游戏的测试。** `nsgotest` 通关测试会站着不动输给电脑，用键盘以必杀技、防御和连段赢下电脑，用两个手柄赢下一场双人对战，并用触屏操作；单元测试逐条检查规则，并检查每个数据文件都是规范形式。

## 操作

| | 玩家 1 | 玩家 2 | 手柄 | 触屏 |
| --- | --- | --- | --- | --- |
| 移动、跳跃、下蹲 | W A S D | 方向键 | 十字键或左摇杆 | 屏幕左半边的摇杆 |
| 轻攻击 | J | . | X / 方块、A / 叉 | L |
| 重攻击 | K | / | Y / 三角、B / 圆 | H |
| 开始、暂停 | Enter | 右 Shift | Start | 暂停 |

在标题画面，每名玩家用左右选择角色，玩家 1 按开始键对战电脑，玩家 2 按开始键开始双人对战。Escape 暂停；在结果画面，Enter 再来一局，Escape 返回标题画面。对战电脑时，玩家 1 可以使用键盘的任意一侧。

## 项目结构

| 文件 | 内容 |
| --- | --- |
| `game.yaml` | 项目文件：窗口、480×270 的虚拟分辨率、两名玩家的输入映射、音效总线和导出预设。 |
| `data/match.yaml` | 规则、电脑对手的参数和角色名单。每名角色包括名字、颜色、体力、速度、两份数据文件，以及帧数据没有说明的部分招式信息：攻击段位、是否为必杀技、如何移动角色、发出的飞行道具，还有电脑对手使用的输入脚本。 |
| `data/<fighter>.moves.yaml` | 角色的招式集（`fighting`）。 |
| `data/<fighter>.frames.yaml` | 角色的帧数据（`framedata`）。 |
| `data.go` | 读取并检查数据；`match.yaml` 的格式定义在这里：带版本号，拒绝未知字段，写回后内容不变。 |
| `match.go` | 一场比赛：回合、计时、命中与伤害、飞行道具和间距。它用两名玩家的输入逐步推进，不关心输入设备和画面。 |
| `player.go` | 一名角色：把识别出的招式变成站立、下蹲或空中的帧数据招式，以及姿势、防御、行走、跳跃和下落。 |
| `cpu.go` | 电脑对手。 |
| `controls.go` | 两名玩家的输入设备。 |
| `game.go`、`hud.go`、`draw.go` | 循环与各个画面、原生 HUD 与菜单，以及 Canvas 绘制。 |

招式集里的招式会播放同名的帧数据招式；下蹲时如果帧数据有 `crouch_<name>` 就播放它，空中播放 `air_<name>`。姿势招式 `idle`、`walk`、`crouch`、`jump`、`guard`、`crouch_guard`、`hurt` 和 `ko` 都循环播放，每名角色都必须有；游戏加载数据时会检查这些，测试也会检查。

## 在哪里修改

- **招式的速度、距离和伤害**：`data/<fighter>.frames.yaml` 中它的框。发生是第一个攻击框生效的帧，收招是最后一个攻击框之后的帧，`cancels` 是可以中途取消的窗口。
- **招式的指令**：`data/<fighter>.moves.yaml`，例如加大 `window` 让指令更容易输入，或用 `charge` 做蓄力招式。
- **招式如何移动、它的段位和飞行道具**：`data/match.yaml` 的 `moves` 中它的条目。
- **新角色**：一份招式集、一份帧数据，以及 `data/match.yaml` 的 `fighters` 中的一个条目，包括电脑使用该角色时的输入脚本。标题画面会列出名单中的每名角色。
- **规则和电脑难度**：`data/match.yaml` 的 `rules` 和 `cpu`，例如 `roundsToWin`、`roundSeconds`、`hitstop`，或电脑的 `block` 概率和 `reaction` 时间。
- **按键和按钮**：`game.yaml` 的 `input`。
- **美术**：`draw.go` 根据框画出图形；可以换成按每名角色正在播放的招式和帧选择的精灵，`framedata.Move.Animation` 可以写上精灵动画的名字。

## 留给游戏的部分

`framedata` 负责结算命中，但把移动和攻击段位留给游戏，所以由 `data/match.yaml` 补上：`motion` 在招式的一段帧内移动角色，`level` 把招式设为下段或中段，`projectile` 把同一份帧数据中的一个循环招式作为投掷者同队的独立角色发射出去。游戏以后要加投技、倒地或必杀槽，也用同样的方式：框写在帧数据里，其余写在比赛文件里。
