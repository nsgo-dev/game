# fps3d 模板

`fps3d` 是一个第一人称射击竞技场，名为 Relay Yard：玩家用一把即时命中的步枪和一具发射弹体的发射器，在一片围墙环绕的场地里抵挡三波无人机和守卫，在战斗间隙拾取生命和弹药。清掉最后一波即获胜，生命降到 0 即失败。它是 3D 射击游戏的起点，也是 3D 相关包协同工作的完整示例：`physics3d`、`render3d`、`ai` 和 `input`。

```sh
go run github.com/nsgo-dev/game/cmd/game@latest new -template fps3d mygame
cd mygame
go tool nsgo dev
```

## 模板展示了什么

- 移动：玩家和每个敌人都是同一个 `physics3d.World` 里的 `physics3d.CharacterController` 胶囊体，能沿墙滑动、迈上台阶和跳跃。墙和箱子是静态盒子，敌人是运动学刚体，玩家会撞上它们，射击也会命中它们。
- 射击：步枪是即时命中，开火瞬间沿墙体层和敌人层做一次 `RaycastFirstLayer`；发射器射出的弹体每一步飞过一段线段，命中后爆炸并造成溅射伤害。弹匣、备弹、换弹和射速都来自竞技场文件，弹匣打空时会自动换弹。
- 敌人：每个敌人运行一棵 `ai` 行为树，由带守卫的分支组成的选择器：看见玩家就攻击，否则去玩家最后被看见或被听见的位置搜寻（一次开枪会惊动听力范围内的所有敌人），再否则沿场地的路线巡逻。敌人沿布局生成的 `pathfind.BoolGrid` 上的 A* 路径行走，路径用 `pathfind.SmoothGridPath` 平滑，并发射玩家可以躲开的光弹。敌人的视线必须与每条墙角保持一段距离，因此它不会隔着一个玩家看不回去的墙角向玩家开火。
- 波次：先倒计时，然后每一波的敌人从出生点逐个进场，两波之间有间歇。
- 渲染：`render3d` 的受光 PBR 管线把关卡烘焙成三个网格（地面、墙和箱子），敌人、弹丸、弹道、拾取物和武器这些会动的东西则都画成同一个单位立方体，每次绘制单独缩放和摆放，光照是一个 `render3d.LightRig`：天空补光、主光以及出生点和拾取物上方的辉光，全部画在一个 `gpu.View` 里。武器在视图空间中绘制，每次开火都会后坐。其上叠着原生 HUD 和一块覆盖层 `core.Canvas`，绘制准星、命中提示、受伤闪红和触屏控件。
- 输入：一个 `input.Actions` 同时接收三种设备。`game.yaml` 的输入映射绑定按键、鼠标按键和手柄的按钮与摇杆；鼠标视角读取锁定指针后的相对移动（`BindPointerAxis` 和 `LockPointer`，每次按下场地时请求一次）；`input.VirtualPad` 在触屏上加入浮动的移动摇杆、浮动的视角摇杆以及开火、跳跃、换弹和切换武器按钮。

| | 键盘和鼠标 | 游戏手柄 | 触屏 |
| --- | --- | --- | --- |
| 移动 | W A S D | 左摇杆 | 左摇杆 |
| 视角 | 锁定指针后的鼠标，或方向键 | 右摇杆 | 视角摇杆（在下方中间拖动） |
| 开火 | 左键或 F | 右扳机 | Fire |
| 跳跃 | 空格 | South | Jump |
| 换弹 | R | West | Reload |
| 下一把武器 | Q，或 1 和 2 | North | Swap |
| 暂停、再玩一次 | P 或 Enter | Start | Play again |

## 项目结构

| 文件 | 内容 |
| --- | --- |
| `game.yaml` | 项目文件：名称、标识符、窗口、导出预设和输入映射。 |
| `arena.yaml` | 关卡和所有玩法数值：用字符画出的布局、玩家、武器、敌人种类、拾取物、波次、开局倒计时和波次间歇。 |
| `arena.go` | 竞技场文件的结构：每个字段都有说明，带版本字段，拒绝未知字段，带校验（边界全是墙、只有一个起点、巡逻路线编号连续、每个空地格子都可到达），编码器的输出读回后完全不变。 |
| `match.go` | 一局游戏：物理世界、玩家的移动和武器、飞行中的弹体、拾取物和波次。它每一步接收一个 `controls` 值，从不直接读取设备，因此结果确定，测试可以直接驱动它。 |
| `enemy.go` | 敌人的身体、行为树、视线和寻路跟随。 |
| `controls.go` | 动作、触屏控件的布局，以及每一步的输入如何变成 `controls`。 |
| `render.go` | 渲染器：烘焙的关卡网格、单位立方体、材质、灯光和每帧的绘制。 |
| `game.go` | 根组件、60 Hz 的 `game.Loop`、暂停和再玩一次、HUD、覆盖层和结束面板。 |
| `*_test.go` | 竞技场文件的往返、拒绝和模糊测试；对局规则；一个会瞄准、开火、横移和回血的机器人；分别用键盘鼠标和手柄打到获胜、站着不动打到失败的完整流程；触屏控件；以及在无头 GPU 上渲染的一帧。 |

建议从竞技场文件读起：`match.go` 的一切行为都由它调节，布局本身就像一张地图。

```yaml
layout:
  - '#################'
  - '#S......#......S#'
  - '#.##.........##.#'
  - '#.#..1..c..2..#.#'
  - '#.....#####.....#'
  - '#..c....H....c..#'
  - '#...#...P...#...#'
```

`#` 是墙，`c` 是矮到可以越过它射击的箱子，`P` 是起点，`S` 是敌人出生点，`1` 到 `9` 依次是巡逻路线，每种拾取物的 `symbol`（这里是 `H` 和 `A`）表示放置该拾取物的位置。

## 在哪里修改

- 关卡：编辑 `layout`。`ParseArena` 会拒绝无法运行的布局，并指出出问题的行和列。
- 平衡：武器的伤害、射击间隔、弹匣和备弹；敌人的生命、速度、视距、视野、攻击距离和光弹；波次的规模和顺序。这些都在 `arena.yaml` 里，完整流程测试会立刻告诉你游戏是否仍然能赢也能输。
- 武器：在 `weapons` 里加一项，类型为 `hitscan` 或 `projectile`。`game.yaml` 已绑定 1 号和 2 号槽位；要加第三把，绑定 `weapon3` 并在 `readControls` 里读取它。
- 敌人行为：在 `newEnemy` 的选择器里、巡逻分支之前加一个带守卫的分支，例如受伤时借助 `ai` 的战术查询退到掩体后。
- 操作：在 `game.yaml` 的输入映射里重新绑定动作，或在 `layoutTouchPad` 里移动触屏控件。
- 外观：修改 `render.go` 顶部的材质和灯光，或者用 `gltf` 加载的网格代替立方体。

模板的测试用 `go tool nsgo test ./...` 运行，除了渲染一帧的那个测试使用 `nsgotest` 提供的无头 GPU 外，都不需要 GPU。
