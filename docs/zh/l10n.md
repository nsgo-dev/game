# l10n

`game/l10n` 基于 NSGo 的 `core` 包和 Go 标准库提供游戏本地化能力：支持 BCP-47 回退链与 CLDR 复数规则的带版本 YAML 和 JSON 字符串表、按文字脚本自动选字体的 `FontSet[F]`、RTL 视觉重排与 HUD 镜像，以及支持按组增量重载的多语言资源目录。

```go
import "github.com/nsgo-dev/game/pkg/l10n"
```

## 字符串表、插值与 CLDR 复数

使用 `Catalog.LoadYAML` 加载按语言拆分的带版本 YAML 字符串表（或继续用 `Catalog.LoadJSON` 加载扁平、嵌套或 CLDR 复数格式的 JSON 表），再用绑定到 `*core.Scope` 的响应式 `Localizer` 读取翻译：

```yaml
# yaml-language-server: $schema=https://game.nsgo.dev/schemas/l10n.v1.json
version: 1
locale: en
strings:
  hud.score: 'Score: {score}'
  menu.play: Play
plurals:
  coins:
    zero: No coins
    one: '{count} coin'
    other: '{count} coins'
```

| 字段 | 含义 |
| --- | --- |
| `version` | 必填，必须为 `1`（`StringTableVersion`）。 |
| `locale` | 必填，规范化 BCP-47 语言标签（如 `en` 或 `zh-Hans`）。 |
| `strings` | 可选，消息键到本地化字符串模板的映射。 |
| `plurals` | 可选，消息键到 CLDR 复数类别（`zero`、`one`、`two`、`few`、`many`、`other`）的映射。 |

```go
cat := l10n.NewCatalog("en")
_ = cat.LoadYAML(enYAML)
_ = cat.LoadYAML(zhHansYAML)

loc := l10n.NewLocalizer(cx, cat)
loc.SetLocale("zh-Hans") // 不设置时默认跟随系统语言

title := loc.T("menu.play")
score := loc.T("hud.score", l10n.Param("score", 420))
coins := loc.Plural("coins", 3)
_, _, _ = title, score, coins
```

YAML 解码严格校验：未知字段、无效复数类别、重复键、在 `strings` 和 `plurals` 中同时出现的键、空键或空复数映射、`null` 值、多余的 YAML 文档、YAML 锚点/别名/合并键、缺失或不支持的版本号（以及非十进制写法如 `0x1`）、以及非规范语言标签（如写作 `zh_hans` 而非 `zh-Hans`）都会被拒绝，且不会修改 `Catalog`。`EncodeYAML` 和 `Catalog.MarshalYAML` 以确定性的 2 空格 YAML 输出，首行写入 `# yaml-language-server: $schema=https://game.nsgo.dev/schemas/l10n.v1.json`（`SchemaComment`）并按字典序排列键名，保证 `EncodeYAML(ParseYAML(b)) == b` 逐字节一致。`ParseYAML`、`ValidateStringTable`、`ApplyStringTable` 与 `Catalog.StringTable` 可直接操作 `*StringTable`，供编辑器的本地化面板等工具使用。

现有的 JSON 字符串表继续通过 `Catalog.LoadJSON` 加载：

```go
cat := l10n.NewCatalog("en")
_ = cat.LoadJSON("en", []byte(`{
	"menu": {"play": "Play"},
	"hud": {"score": "Score: {score}"},
	"coins": {"zero": "No coins", "one": "{count} coin", "other": "{count} coins"}
}`))
_ = cat.LoadJSON("zh-Hans", []byte(`{
	"menu": {"play": "开始游戏"},
	"hud": {"score": "得分：{score}"},
	"coins": {"other": "{count} 枚金币"}
}`))
```

查找会沿规范化后的 BCP-47 回退链逐级解析（如 `zh-Hans-CN` -> `zh-Hans` -> `zh` -> 回退语言），全部缺失时原样返回键名。也可以通过 `cat.Set` 和 `cat.SetPlural` 以代码方式写入词条。

### CLDR 复数规则与死分支审计

`Catalog.Plural`、`Localizer.Plural` 与 `PluralCategoryFor` 使用由 **Unicode CLDR 48.2**（`CLDRVersion`，`common/supplemental/plurals.xml`）生成的纯整数基数复数规则，无额外运行时依赖。由于 `Plural` 仅接受整数计数（`int`），CLDR 的小数与紧凑格式操作数（`v`、`w`、`f`、`t`、`c`、`e`）恒按 `0` 处理，负数按绝对值计算。

- **BCP-47 匹配**：规则沿规范化后的 BCP-47 子标签链匹配，未收录的语言回退至 CLDR `root`（`other`），因此具有独立规则的地区变体（如 `pt-PT` 与 `pt-BR`）以及带地区子标签的语言（如 `cs-CZ` -> `cs`）都能自动命中正确类别。
- **显式 `zero` 覆盖**：当 `count == 0` 且词条提供了非空 `zero` 形式时，无论该语言在 CLDR 中是否有 `zero` 类别，`Plural` 都会优先返回 `zero`（例如英语中的 `"No coins"`）。若省略 `zero`，则 `count == 0` 按该语言的 CLDR 规则选择（英语为 `other`，法语与 `pt-BR` 为 `one`，罗马尼亚语为 `few`，俄语与波兰语为 `many`）。
- **死分支审计**：`Catalog.CheckPlurals`、`CheckStringTablePlurals`、`UnusedPluralForms` 以及 `assetcheck`（`game check`）会报告表中提供但该语言整数 CLDR 规则永远不会选中的复数类别（例如英语中的 `few`、中文中的 `one`，或捷克语、立陶宛语中仅用于小数的 `many`）。`zero`（可通过显式 `zero` 覆盖命中）与 `other`（通用回退形式）不会被报告。也可直接通过 `PluralCategories(locale)` 查询指定语言在整数下可达的复数类别。

## 按文字脚本选字体（`FontSet[F]`）

为混合文字场景配置按脚本或按语言映射的字体集（支持任意字体类型 `F`，例如 `*text.BitmapFont` 或 `core.Font`）：

```go
fonts := l10n.NewFontSet(latinFont)
fonts.SetScript(l10n.ScriptCJK, cjkFont)
fonts.SetScript(l10n.ScriptArabic, arabicFont)
fonts.SetLocale("ja", jpFont)

// 将混排文本切分为连续片段，每段附带匹配好的字体：
runs := fonts.RunsForText(loc.Locale(), "Score: 120 得分")
for _, run := range runs {
	drawRun(run.Text, run.Font)
}
```

也可直接调用 `RuneScript`、`DetectScript`、`SegmentByScript` 与 `LocaleScript` 进行脚本检测。

### 从字符串表烘焙位图字体

无需在 `game.yaml` 中手工维护中日韩或多语言字符表，只需将字体目标的 `charsFrom` 指向 YAML 或 JSON 字符串表（并可选通过 `charsFile` 补充额外字符）。`go tool game assets` 会自动剥离 `{placeholders}` 占位符与富文本标记，将所有字符串和复数形式与 `chars` 合并，并且只在最终排序后的字符集发生变化时才重建字体；当源字体文件本身缺少某个字符时会输出警告。`go tool game check` 会校验对应语言字符串表中的每条文案与复数形式是否都能由该字体目标绘制（见[命令行](cli.md#assets)）。在 Go 工具代码中，也可直接使用 `l10n.StripPlaceholders`、`StringTable.CollectChars` 和 `l10n.ValidateLocale`。

资产构建和资产检查使用同一个排序字符集契约，因此没有新增字符的文本表修改会保持字体缓存有效，而缺失字符会带着本地化键名和源文件行号报告。

## RTL 视觉排序与布局镜像

通过 `LocaleDirection`、`EnvDirection` 或 `TextDirection` 查询书写方向。对于按从左到右逐字绘制的自定义画布文本渲染器，使用 `VisualOrder`（或 `loc.Visual(s)`）将逻辑字符串转为视觉顺序：

```go
dir := loc.Direction()
visual := loc.Visual(loc.T("hud.greeting"))
aligned := l10n.LayoutAlignment("start", dir) // LTR 下为 "left"，RTL 下为 "right"
x := l10n.MirrorX(16, iconW, screenW, dir)
_, _, _ = visual, aligned, x
```

## 多语言资源目录（`AssetCatalog`）

用 `AssetCatalog` 管理按语言区分的配音、贴图或标题横幅，可从任意 `io/fs.FS` 自动发现（支持 `locales/<locale>/<name>`、`<name>.<locale>.<ext>` 与 `<name>_<locale>.<ext>`），也可通过 `LoadAssetManifestYAML` 加载 YAML 资源清单：

```go
assets, err := l10n.DiscoverFS(embedFS, "en")
if err != nil {
	return err
}
assets.RegisterGroup("voice", "voice/intro.wav", "voice/boss.wav")

// 切换语言时仅重载解析路径真正发生变化的资源组：
stop := assets.OnReload(func(groups []string, locale string) {
	reloadAssetGroups(groups, locale)
})
defer stop()

assets.SetLocale("ja")
resolved, ok := assets.Resolve("voice/intro.wav", assets.Locale())
_, _ = resolved, ok

// 在测试或 CI 中审计缺失变体：
for _, rep := range assets.CheckMissing("ja", "zh-Hans", "ar") {
	if !rep.Complete() {
		log.Printf("%s missing %v (%.0f%%)", rep.Locale, rep.Missing, rep.Coverage*100)
	}
}
```

使用 `assets.WatchLocale(cx, localeSignal, reloadFn)` 可直接监听响应式 `core.Signal[string]` 并在语言切换时触发增量重载。

### 资源清单

资源清单是带版本号的 YAML 文件，列出每个逻辑资源在各语言下的路径，以及切换语言时需要重载的资源组：

```yaml
version: 1
base_locale: en
assets:
  voice/intro.wav:
    en: locales/en/voice/intro.wav
    ja: locales/ja/voice/intro.wav
    zh-Hans: locales/zh-Hans/voice/intro.wav
groups:
  voice:
    - voice/intro.wav
```

| 字段 | 含义 |
| --- | --- |
| `version` | 必填，必须为 `1`。 |
| `base_locale` | 可选的回退语言；设置后替换目录的基础语言。 |
| `assets` | 逻辑资源名到「语言 → 路径」映射。每个资源至少有一个变体，路径不能为空。 |
| `groups` | 资源组名到其重载的资源名列表，不能重复。资源组可以引用清单之外登记的资源，例如 `DiscoverFS` 发现的资源。 |

用 `LoadAssetManifestYAML` 把清单合并进目录（覆盖目录中已有的同名变体），用 `MarshalAssetManifestYAML` 把目录写回清单：

```go
if err := assets.LoadAssetManifestYAML(data); err != nil {
	return err
}
out, err := assets.MarshalAssetManifestYAML()
```

解码是严格的：未知字段、重复键、第二个 YAML 文档、缺失或不支持的版本号以及不写作 `1` 的版本号（如 `1.0`、`0x1`）、YAML 锚点、别名和 `<<` 合并键、不规范的资源名（如 `./ui/a.png`）、不是规范化 BCP-47 标签的语言（如 `zh_hans`，应写作 `zh-Hans`）都会被拒绝，错误信息会指出具体位置，且不会合并任何内容。输出是确定的：字段按 schema 顺序、键排序、资源组成员排序、不含时间戳，因此以这种方式保存的清单再次加载并保存后逐字节不变。保存时写出的是这种规范形式而不是输入原文，所以手写清单第一次保存时会去掉注释，并改写流式写法、引号、顺序以及空的 `assets` 或 `groups` 条目；此后每次保存文件都不再变化。需要编辑清单的工具可以直接用 `ParseAssetManifest`、`ValidateAssetManifest`、`EncodeAssetManifest`、`ApplyAssetManifest` 和 `AssetCatalog.AssetManifest` 处理 `AssetManifest` 值。
