# Platform support

NSGo Game targets six primary build targets (macOS, Windows, Linux, iOS, Android, and Web) and also compiles with NSGo's four experimental targets (HarmonyOS, tvOS, watchOS, and mini programs), though feature availability and CI test coverage differ by target. Every cell below is verified against NSGo `v0.3.4` and this repository's build tags and workflows, with links to the upstream issue tracking each gap.

- **Supported**: works in NSGo `v0.3.4` and `nsgo-dev/game` without missing platform plumbing.
- **Partial (N)**: works with platform limits or missing pieces explained in [Footnotes](#footnotes).
- **Not available**: returns an unsupported/unavailable error or is excluded at compile time; links the tracking issue.
- **Out of scope**: the platform has no native equivalent or the feature does not belong on that target.

## Footnotes

1. **HarmonyOS 2D rendering**: `Canvas` replays onto an ArkUI `Canvas`, but `core.Shader` has no view host on HarmonyOS yet (`docs/architecture/harmonyos.md`; tracked in [nsgo#1521](https://github.com/nsgo-dev/nsgo/issues/1521) and [nsgo#1320](https://github.com/nsgo-dev/nsgo/issues/1320)).
2. **watchOS 2D rendering**: `Canvas` draws on the SwiftUI host, while `KindShader` renders as an empty box because watchOS has no Metal view (`internal/platform/watchos/watchos.go`; [nsgo#1318](https://github.com/nsgo-dev/nsgo/issues/1318)).
3. **Mini programs 2D rendering**: `Canvas` draws into an offscreen canvas (`canvas2d`), WeChat supports pixel images while QQ, Douyin, and Alipay lack image-view pixel binding, `nsgo_noshader` disables `core.Shader`, and the 2 MB package cap constrains bundled code and assets (`docs/architecture/miniprogram.md`; [nsgo#1505](https://github.com/nsgo-dev/nsgo/issues/1505)).
4. **Windows and Android audio**: `Env.CanPlayAudio()` is true on both (XAudio2 + Media Foundation on Windows; SoundPool + MediaPlayer on Android, with SoundPool's 1 MiB decoded sample cap), while `Env.CanScheduleAudio()` is false (`windows/env.go` and `android/protocol.go` do not set `AudioSchedule`, so timed sample scheduling is unavailable).
5. **Web audio**: Web Audio (`AudioContext`) and `HTMLAudioElement` are supported, but browsers mute output until the first trusted user gesture (`docs/architecture/audio.md`; see [sound](sound.md)).
6. **iOS, Android, and HarmonyOS keyboard and mouse**: external hardware keyboards dispatch `EventKeyDown` / `EventKeyUp`, but `Env.CanLockPointer()` and `Env.SupportsCustomCursor()` are false (no desktop pointer lock or custom image cursor).
7. **tvOS keyboard and mouse**: Apple TV uses the Siri Remote for focus navigation (`ios/keycommands.go` skips hardware key commands when `onTV()`); mouse pointers and pointer lock are absent ([nsgo#1317](https://github.com/nsgo-dev/nsgo/issues/1317)).
8. **Desktop touch**: macOS has no touchscreen hardware and maps mouse presses as finger 0 for views that listen to `OnTouch` (`macos/macos.go`). Windows (`WM_POINTER` in `windows/touch.go`) and Linux (GTK touch events in `linux/callback.go`) support multi-touch on touchscreen hardware in addition to pointer input.
9. **Web haptics**: `mobile.PlayHapticPattern` uses `navigator.vibrate` where the browser implements the Vibration API (primarily Android browsers); `mobile.PlayHaptic` is a no-op and Safari/iOS lacks `navigator.vibrate` (`web/env.go`, `web/haptics.go`).
10. **Web motion sensors**: `WatchMotion` reads `DeviceMotionEvent` and `DeviceOrientationEvent` in secure mobile browser contexts only (Safari requires `RequestPermission(PermissionMotion)` from a user gesture); desktop browsers and magnetometers report unavailable (`docs/architecture/location-motion.md`; [nsgo#1208](https://github.com/nsgo-dev/nsgo/issues/1208)).
11. **Web and mini program local saves**: `save.StorageBackend(cx.Storage(), ...)` persists to browser `localStorage` or mini program host storage, but `cx.DataDir()` is empty so `save.FileBackend` does not apply (`pkg/save/backend.go`).
12. **HarmonyOS local saves**: `internal/platform/harmonyos/harmonyos.go` passes no persistent `Storage` store to `engine.Start`, so `cx.Storage()` falls back to an in-memory store (`core.NewStore(nil)`) and `js/wasm` cannot write directly to host paths in `DataDir` ([nsgo#1521](https://github.com/nsgo-dev/nsgo/issues/1521), [nsgo#1320](https://github.com/nsgo-dev/nsgo/issues/1320)).
13. **macOS OS cloud save**: Apple iCloud ubiquity containers require a provisioning profile with iCloud entitlements, which NSGo embeds only in Mac App Store builds (`sign.macos_profile`); Developer ID and ad hoc builds leave iCloud out and return `ErrCloudUnavailable` (`docs/architecture/cloud.md`).
14. **Android OS cloud save**: Google Play Games Saved Games works via `CloudStorage.java` reflection only when the Play Games Services SDK is packaged with the app/host and the player is signed in; otherwise `Env.CanUseCloudStorage()` is false and `liveops.PlatformCloud` returns `ErrCloudUnavailable` (`docs/architecture/cloud.md`, `android/protocol.go`).
15. **HarmonyOS self-hosted cloud save**: `liveops.CloudClient` runs Go's `net/http` over ArkWeb's `fetch`, requiring network permission and CORS `allowedOrigins`, and is not tested in CI ([nsgo#1521](https://github.com/nsgo-dev/nsgo/issues/1521), [nsgo#1320](https://github.com/nsgo-dev/nsgo/issues/1320)).
16. **Web and HarmonyOS WebSocket**: `pkg/online/netplay/ws_js.go` wraps the browser `WebSocket` global for client `DialWebSocket` only (`ListenWebSocket` is native-only). On HarmonyOS this runs inside ArkWeb and is not tested in CI ([nsgo#1521](https://github.com/nsgo-dev/nsgo/issues/1521), [nsgo#1320](https://github.com/nsgo-dev/nsgo/issues/1320)).
17. **Android game services**: the Go wire protocol (`gameservices_android.go`) is implemented, but NSGo `v0.3.4`'s prebuilt `NsgoView.java` does not yet set the Play Games Services capability bit (`more & 64`), so `Env.CanUseGameServices()` is false and `achievements` / `leaderboard` return `ErrUnsupported` until the Java reflection hook lands (`docs/architecture/gameservices.md`).
18. **Linux and Web local notifications**: immediate notifications work, and `Env.CanScheduleNotifications()` is true, but scheduled notifications are held in memory by `driver.NotificationScheduler` and fire only while the app or browser page remains open (`linux/env.go`, `web/env.go`, `docs/architecture/services.md`).
19. **Steam integration**: `pkg/online/presence` (`ISteamFriends` via `purego`), `pkg/modding` (`SteamWorkshop` via `purego`), and `liveops.DirCloud` (Steam Auto-Cloud) build and run on macOS, Windows, and Linux, but running NSGo games under the Steam client, Steam Linux Runtime, Steam Deck / gamescope, Steam Overlay, and Steam Input is still being verified in [nsgo#1228](https://github.com/nsgo-dev/nsgo/issues/1228).
20. **Windows CI**: `.github/workflows/check.yml` cross-compiles and vets `windows` with `go tool nsgo check`, but `.github/workflows/test.yml` does not yet run `go tool nsgo test ./...` on a Windows runner (tracked in [game#1305](https://github.com/nsgo-dev/game/issues/1305)).
21. **iOS and Android CI**: `.github/workflows/check.yml` compiles and vets `ios`, `ios_simulator`, and `android` with `go tool nsgo check`, but runtime tests and example smoke runs on an iOS simulator and Android emulator are not yet in CI (tracked in [game#1306](https://github.com/nsgo-dev/game/issues/1306)).
22. **Web CI**: `.github/workflows/check.yml` cross-compiles and vets `web` with `go tool nsgo check` and `.github/workflows/website.yml` builds the WebAssembly playground examples, but headless browser runtime tests do not run in `nsgo-dev/game`'s CI.

## Experimental targets

HarmonyOS, tvOS, watchOS, and mini programs are outside the first stage of NSGo Game and are not built or vetted by this repository's CI. In NSGo `v0.3.4`, all four disable `Env.SupportsGPU()` and `Env.CanPlayAudio()`, so a 3D game renders an empty fallback view and any game using `pkg/sound` runs silent:

- **HarmonyOS**: preview ArkWeb + ArkUI target; lacks GPU views, audio, gamepads, haptics, motion sensors, persistent `core.Storage`, native notifications, UDP, and game services ([nsgo#1521](https://github.com/nsgo-dev/nsgo/issues/1521), [nsgo#1320](https://github.com/nsgo-dev/nsgo/issues/1320)).
- **tvOS**: shares the iOS backend with gamepads, Game Center, StoreKit, and iCloud, but `ios/env.go` disables audio and GPU views until tvOS verification finishes ([nsgo#1317](https://github.com/nsgo-dev/nsgo/issues/1317)).
- **watchOS**: SwiftUI host with 2D `Canvas`, touch, motion sensors, local saves, and local notifications, but no Metal/GPU view, no audio, no gamepads, no haptics, no iCloud, and no Game Center ([nsgo#1318](https://github.com/nsgo-dev/nsgo/issues/1318)).
- **Mini programs** (WeChat, QQ, Alipay, Douyin): logic-layer `js/wasm` with `nsgo_noshader` and a 2 MB package cap; no GPU view, no audio, no gamepads, no haptics, no motion sensors, and no standard browser `fetch` or `WebSocket` globals ([nsgo#1505](https://github.com/nsgo-dev/nsgo/issues/1505)).

## Out of scope

- **Game consoles** (Nintendo Switch, PlayStation, Xbox): console SDKs are under NDA and require C toolchains, whereas NSGo and NSGo Game are pure Go with no hand-written C.
- **VR and AR**: currently out of scope until NSGo exposes an XR runtime ([#495](https://github.com/nsgo-dev/game/issues/495); see [VR and AR](index.md#vr-and-ar)).
- **Target-specific exclusions**: desktop operating systems have no OS-wide cloud save daemon (use `liveops.DirCloud` with Steam Auto-Cloud or `liveops.CloudClient` over [cloudsave](cloudsave.md)), desktop targets have no mobile haptic or Core Motion APIs, browsers cannot open raw UDP sockets, Steamworks is desktop-only, and the visual [Scene Editor](editor.md) is a desktop tool.

See [Building and Shipping](shipping.md) for packaging, signing, notarization, store channels, and `nsgo check` commands across the six primary build targets.
