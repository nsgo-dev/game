# Agent Note: Net wire message schema in YAML with zero-allocation Go codecs

Status: implemented

## Problem

Every `pkg/online/netplay` wire protocol (transport frames, UDP sealed datagrams, connection handshake, relay frames and control bodies, replication v2, lockstep/rollback inputs, and mid-match membership) was previously hand-coded and documented only in comments, with mixed big-endian and little-endian byte orders, unquantized raw 32-bit floats, and opaque `EntityState.Props` byte slices. Adding packet inspection (`game net decode`), cross-language clients, or typed game payloads required duplicating ad-hoc binary parsers while keeping bit-exact determinism across amd64 and arm64 and zero allocations on hot paths.

## Decision

We introduce a versioned YAML wire schema format in `pkg/online/netplay/wire` (`version: 1`, JSON Schema `https://game.nsgo.dev/schemas/wire.v1.json` generated by `tools/gameschema`) and a deterministic pure-Go codec generator in `cmd/gamewire`. All seven existing `pkg/online/netplay` wire protocols are described verbatim under `pkg/online/netplay/wire/*.wire.yaml` without changing a single wire byte (`ReplicationVersion` remains `2` and `hsVersion` remains `1`), with differential fuzz tests proving byte-identical encoding and matching decoding against `pkg/online/netplay`.

## Schema format

Schema files (`*.wire.yaml`) follow the repository's strict YAML text-format rules enforced by `internal/formattest`: top-level `version: 1`, unknown and duplicate keys refused, single YAML document per file, canonical deterministic `wire.Encode` output prefixed with the `yaml-language-server` `$schema` header, and sibling cross-file references via `imports`.

The type system covers fixed-width unsigned and signed integers (`u8`..`u64`, `i8`..`i64`) with explicit `order: be|le`, `uvarint`, `svarint` (zigzag), `bool`, raw `f32`, integer-only `qfloat {min, max, bits}` and `fixed {scale, type}`, length-prefixed or trailing (`length: rest`) `bytes` and `string` (defaulting to `uvarint` length), fixed-count and length-prefixed `array`, validated `enum`s, MSB-first bit-packed `bits {bits: n}`, presence-bitmask `mask` groups with `delta: true`, and `union`s discriminated by `u8`, `u16`, `uvarint`, or a 1-byte `nibble` split (such as replication v2's 4-bit version and 4-bit message type).

Integer-only quantization (`QuantizeFloat`, `DequantizeFloat`, `QuantizeFixed`, `DequantizeFixed`, `QuantizeFixedUint`, `DequantizeFixedUint`) decomposes IEEE-754 bit patterns into integers and performs all scaling, division, and rounding with `math/bits` integer arithmetic only—emitting zero floating-point arithmetic instructions so amd64, arm64, WebAssembly, and future TypeScript `BigInt` decoders produce identical bytes and values.

## Codegen contract

`cmd/gamewire` (run through `go generate` and checked in CI with `-check`) emits `gofmt`-formatted, deterministic Go files with minimal imports:

- Every message and union `X` generates `AppendX(dst []byte, m *X) []byte` and `DecodeX(src []byte, m *X) (int, error)`.
- `DecodeX` fills caller-owned storage and reuses slice backing capacities for `bytes` and variable-length `array` fields (including nested slices), achieving zero steady-state heap allocations verified by `debug.AssertZeroAllocs`.
- `DecodeX` checks variable-length `array` counts against remaining input bytes before growing slices, preventing malformed packets from causing large allocations.
- `union` structs store variant payloads by value rather than `any` interfaces, keeping union decode allocation-free.
- `mask` groups with `delta: true` generate `DiffX(base, cur *X)` (comparing float fields via `math.Float32bits` / `math.Float64bits` and byte slices via `bytes.Equal`) and `ApplyX(dst, delta *X)` (copying masked fields while reusing slice capacity).
- `pkg/online/netplay/wire` embeds all seven built-in schemas in `wire.BuiltinFS` / `wire.LoadBuiltins()` so downstream packet inspection (`#1302`) and cross-language codegen (`#1304`) read the single source of truth directly.

## Alternatives considered

### Protocol Buffers (protobuf)

Protobuf offers a mature schema ecosystem, built-in `protoc --decode` inspection, and code generators for almost every language. It is rejected because every field carries a wire tag, it has no bit packing or quantized float types, its encoding is not canonical (breaking deterministic checksums and golden vectors), the Go protobuf runtime allocates on decode, and every game would require installing `protoc` and language plugins.

### FlatBuffers

FlatBuffers provides zero-copy, zero-allocation reads from byte buffers and cross-language code generation without unpacking. It is rejected because vtables, alignment padding, and relative offsets bloat small 60 Hz gameplay packets relative to bitmask deltas and varints, it lacks bit packing and integer-quantized floats, it cannot represent existing `pkg/net` wire formats verbatim without a breaking protocol rewrite, and it requires the external `flatc` C++ compiler toolchain.

### Cap'n Proto

Cap'n Proto also gives zero-copy reads, canonical packing mode, and cross-language bindings. It is rejected for the same reasons as FlatBuffers: 64-bit word alignment and pointer framing cannot describe the compact existing `pkg/net` wire layouts without changing wire bytes, it provides no bit-packed fields or architecture-independent quantized floats, and it depends on an external `capnp` compiler binary.

## Consequences

### Benefits

- All seven `pkg/online/netplay` wire formats have one machine-readable, schema-validated YAML specification with differential fuzz proofs of byte-for-byte equivalence and zero-allocation generated Go codecs.
- Pure-integer `qfloat` and `fixed` codecs eliminate arm64/amd64 FMA drift by construction and establish golden vectors verified in CI on both architectures.
- Games can reuse `cmd/gamewire` for typed `EntityState.Props` and custom packets without adding third-party dependencies or external toolchains.
- Downstream issues (`#1302` packet capture/inspector and `#1304` TypeScript codecs and cross-language golden vectors) consume `pkg/online/netplay/wire`'s parsed `Schema` AST and `BuiltinFS` directly.

### Costs

- Adding or changing a wire message requires updating its `*.wire.yaml` file and re-running `go generate ./pkg/online/netplay/wire` (enforced in CI by `cmd/gamewire -check` and `TestGeneratedCodecsUpToDate`).
- Production call sites in `pkg/online/netplay` remain on their existing hand-written codecs in this first rollout step until follow-up work switches them over, so both code paths coexist temporarily while guarded by differential fuzz tests.
- Go `string` immutability means hot-path fields whose text changes every frame still allocate unless modeled as `bytes`; docs and examples call this out explicitly.
