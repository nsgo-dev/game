# Agent Note: age gate and child mode

Status: implemented

## Problem

Games had no shared age question or persisted child-mode decision, so privacy-sensitive features could remain enabled after a player identified as a child.

## Decision

Add `liveops.AgeGate` with four age bands, a version-independent JSON record containing only the band and asked-at time, and a caller-supplied text storage adapter. Missing or corrupt records fail closed as child mode.

## Consequences

Analytics, personalization and link or purchase flows can gate on one decision without retaining a date of birth. Consent-purpose integration and the visual parental gate remain follow-up work.

## Alternatives considered

Persisting a date of birth was rejected because the game only needs a policy band and should minimize sensitive data. Treating malformed data as adult was rejected because it would fail open.
