# Agent Note: Editor Spec light theme, WCAG contrast verification, and live system appearance repainting

Status: implemented

## Problem

The editor's Settings screen (`docs/design/editor/Settings.dc.html`) and [editor i18n and appearance settings](./2026-11-25-editor-i18n-and-appearance.md) support choosing `system`, `light`, or `dark` appearance, but `docs/design/editor/Spec.dc.html` only defined dark token values and `EditorView` did not attach a custom `core.Theme`. As a result, choosing `light` (or running with `system` on a light OS) fell back to NSGo's generic default theme instead of the editor Spec's surface hierarchy, overlay contrast guarantees, and accessible accent/warning rules, while several editor chrome elements stayed hardcoded to dark colors.

## Decision

The editor embeds a single plain-text YAML theme file (`packages/game/editor/spec_theme.yaml`) parsed strictly through `core.ParseTheme` with coordinated `dark` and `light` palettes, applies it on `EditorView`'s root scope via `cx.SetTheme(SpecTheme())`, and exposes a structured `SpecPalette` API measured against one shared WCAG 2.2 contrast table.

### Key design choices

- **Single embedded YAML theme file (`spec_theme.yaml`) for both appearances**: `SpecTheme()` parses `spec_theme.yaml` via `core.ParseTheme`, mapping every NSGo `core.Palette` and `ui.Colors` role (`background`, `surface`, `raised`, `inset`, `line`, `border`, `text`, `textMuted`, `accent`, `accentFill`, `accentHover`, `accentPressed`, `accentText`, `light`, `onLight`, `success`, `warning`, `danger`, `focus`, `info`) plus every Spec-specific token (`bg`, `panel`, `raised`, `inset`, `viewport`, `viewportDot`, `pillBg`, `line`, `lineRaised`, four text levels, and `Accent`/`Agent`/`Added`/`Changed`/`Removed`/`Warning` semantic roles with `Fg`, `Fill`, `Edge`, and `OnFill`). Every NSGo `ui` widget automatically follows the Spec palette in both appearances.
- **Cool blue-slate light palette preserving every Spec role**: Light surfaces invert the dark elevation ladder while keeping the Spec's cool blue-slate tone (`bg #EEF1F6`, `panel #F6F7FA`, `raised #FFFFFF`, `inset #E5E9F0`, `viewport #EAEFF6`, `line #D5DBE5`, `line raised #DCE1EB`) and four AA/AAA text levels (`#101216`, `#222733`, `#444C5E`, `#535C6E`). Light semantic hues (`accent #1D5CE6`, `agent #6A3DE8`, `added #0D7A43`, `changed #9A5B00`, `removed #C92A2A`, `warning #855300` on fill `#FDF4DC` / edge `#C99A2E`) preserve the exact Spec hue families while deepening luminance so text on surfaces/pills and `#FFFFFF` on solid fills both pass WCAG 2.2 AA (`>= 4.5:1`) and overlay edges on the light viewport surround exceed `3:1` (4.68:1–4.88:1).
- **One WCAG 2.2 contrast table for both palettes**: `ContrastRatio` (with `RelativeLuminance` and `CompositeOver`) and `SpecContrastTable` evaluate the exact same 44 foreground/background, on-fill, warning-card, pill-text, and viewport-overlay pairs for both `DarkSpecPalette()` and `LightSpecPalette()`. `TestSpecContrastTableDarkAndLight` enforces every threshold (`>= 4.5:1` for text/pills/on-fill, `>= 3.0:1` for UI/overlay edges) and cross-checks all 19 published dark ratios from `Spec.dc.html`. `TestSpecNoWhiteOnFailingAccentOrAgent` guards against ever placing white ink on dark `#3B7BFF` (3.84:1) or `#9B7BFF` (3.15:1).
- **Live system appearance repainting without restart**: `EditorView` binds `cx.SetTheme(SpecTheme())` and keys `chromeKey` on `(ed.ResolvedLanguage(), cx.Dark())`, while `Editor.Dark()` and `Editor.SpecPalette(cx)` read `cx.Dark()`. When `Appearance` is `AppearanceSystem`, OS appearance transitions update `cx.Env().Dark()`, immediately repainting all panels, NSGo controls, viewport overlays, the compact overlay legend (`viewportOverlayLegendView`), and toasts (`ToastView`) without restarting.
- **Spec feedback components and macOS screenshot verification**: `spec_feedback_ui.go` provides the Spec toast queue (`Editor.ShowToast`, `DismissToast`, `ToastView`, `SpecToastCard`) and overlay legend (`SpecOverlayLegendView`, `Editor.SetOverlayLegendOpen`) styled exclusively with `SpecPalette`. `packages/game/editor/editorcmd/theme_screenshot_test.go` captures real native macOS `nsgotest` screenshots of the editor, overlay legend, and toasts in both dark and light modes.

## Alternatives considered

- **Defining light colors only in Go structs without `core.ParseTheme` / `cx.SetTheme`**: rejected because NSGo `ui` widgets (`ui.Button`, `ui.ToggleButton`, `ui.Dialog`, `ui.TextField`) read their colors from `cx.Palette()` / `ui.ColorsOf(cx)`; without `cx.SetTheme(SpecTheme())`, standard controls would fall back to `core.DefaultTheme()` in light mode and break Spec token consistency.
- **Reusing the dark semantic hex values (`#3B7BFF`, `#4FD38A`, `#E9A84A`, `#FF6B6B`, `#F2C14E`) verbatim on light surfaces**: rejected because bright pastel-saturated dark-mode tokens fail WCAG 2.2 AA (`4.5:1`) for text and pill labels on white/light-slate backgrounds (for example `#4FD38A` on `#FFFFFF` is only `1.94:1` and `#E9A84A` on `#FFFFFF` is `2.16:1`). Deepening each semantic hue for light mode preserves hue identity while passing every contrast threshold.
- **Forcing `#101216` dark ink on light `Accent` fills**: rejected because darkening `#1D5CE6` enough to reach `>= 4.5:1` against light surfaces (`4.88:1` on viewport, `5.64:1` on raised) simultaneously gives `#FFFFFF` on `#1D5CE6` a `5.64:1` AA ratio (and `7.11:1` / `8.68:1` on hover/pressed), whereas dark ink on `#1D5CE6` would fail `4.5:1` (`3.32:1`). The Spec rule is enforced structurally: `OnFill` must always pass `>= 4.5:1` on `Fg`, never white when white fails.

## Consequences

- **Benefits**: Full Spec token fidelity in both Dark and Light modes across all NSGo `ui` controls and custom Spec views; deterministic CI enforcement of all 44 WCAG 2.2 contrast pairs in both palettes; live OS light/dark switching without restart; reusable Spec toast and overlay legend views verified with real macOS screenshots.
- **Costs**: Any future adjustment to `spec_theme.yaml` must keep all 44 `SpecContrastTable` pairs above their WCAG thresholds in both palettes (enforced by `TestSpecContrastTableDarkAndLight`), and remaining legacy panels that still reference the older package-level dark `spec*` vars should migrate to `ed.SpecPalette(cx)` as those screens are updated.
