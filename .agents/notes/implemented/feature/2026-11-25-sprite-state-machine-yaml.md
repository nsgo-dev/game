# Agent Note: Sprite state machines in `*.states.yaml`, graph editor, and MCP tools

Status: implemented

## Problem

Flipbook clips (`*.animation.yaml`) in `game/animclip` play a single clip on an object, leaving character locomotion (`idle → run → jump → fall → run`) and interrupt transitions (`Any state → hurt`) to ad-hoc Go switches scattered across gameplay code. Authors could not author, preview, key-drive, or validate sprite transition graphs in plain-text YAML, and coding agents using `game/editor/editormcp` had no structured way to write a state machine file and verify it against scripted input (#1054).

## Decision

Sprite state machines live inside the existing `game/animclip` package alongside clip playback and share the `game.Loop` fixed-step clock, built-in `sceneformat` component registry, `refs`/`assetcheck` pipeline, `editor` undo history, and `editor/editormcp` server:

- **Versioned YAML format (`*.states.yaml`)**: `animclip.StateMachineDoc` (`StateMachineVersion = 1`, JSON Schema `https://game.nsgo.dev/schemas/states.v1.json` generated by `cmd/gameschema`) declares `entry`, typed `parameters` (`float`, `bool`, `trigger`), `states` (`name`, `clip`, optional `x`/`y` graph layout), and ordered `transitions` (`from` including wildcard `'*'`, `to`, `when`, `onEnd`). `ParseStateMachine` refuses unknown fields (`KnownFields(true)`), compiles and type-checks every `when` expression at load time, and returns `*StateMachineError` carrying the YAML key `Path` so `assetcheck` pinpoints exact `file:line` diagnostics. `EncodeStateMachine` writes deterministic canonical YAML with the `# yaml-language-server` schema directive and lossless round-trip verified by `formattest.Run`.
- **Built-in `animator` component (`sceneformat/animator.go`)**: `sceneformat.AnimatorComponent()` registers `animator` with string fields `states` and `startClip`, registered automatically in the editor's built-in component registry so scenes stay valid at `version: 1` and `version: 2` without a scene schema bump.
- **Deterministic runtime (`animclip.StateMachine`)**: `NewStateMachine` and `NewAnimator` resolve every state's clip up front through `ClipResolver` (implemented by `*resource.Library` via `Library.Animation`, `ClipMap`, and `FSClips`), advance strictly on `Update(dt)` fixed steps, evaluate outgoing state transitions in declared order followed by `Any state` (`'*'`) interrupts, and auto-consume triggers when fired or at step end.
- **Shared input driver and simulator (`animclip.InputDriver`, `animclip.SimulateStateMachine`)**: `InputDriver` translates project `input.Actions` (`move_left`, `move_right`, `jump`, `attack`, `hurt`) into locomotion parameters (`move.x`, `velocity.y`, `on_floor`, `jump`, `attack`, `hurt`) using a simple deterministic kinematics step. Both the editor's **Drive with keys** preview and `SimulateStateMachine` (used by `states_test` MCP tool) drive the same `animclip.StateMachine`, guaranteeing identical state transitions and active sprite frames in editor preview and game runtime.
- **Validation and reference tracking**: `refs.Scan` records `KindStates` files, `animator.states` references on objects and overrides, and `states[].clip` references so `refs.PlanMove` rewrites both clip and states paths. `tooling/assetcheck` validates every `*.states.yaml` file and `animator` component, refusing missing target states, unknown clips, and unread parameters (`doc.UnusedParameters()`) with exact `file:line`.
- **Editor graph panel (`editor/states.go`, `editor/states_ui.go`)**: Opens `*.states.yaml` from the file browser, command palette, or API; renders state node cards with sprite thumbnails and clip metadata, directed labelled transition arrows, `Any state` badge, live active-state highlight, **Drive with keys** switch and key pills, and `LEAVING <STATE>` outgoing transition list using only Spec color tokens (`Spec.dc.html` / `Animation.dc.html`). Every graph edit flows through the editor's undo/redo history.
- **Editor MCP tools (`editor/editormcp/states.go`)**: Registers `states_write` (validates, writes canonical YAML inside the project root, and opens the graph in the editor without touching the file on refusal) and `states_test` (runs `SimulateStateMachine` and returns trace, visited states, stuck states, and summary such as `"Played 8 s of scripted input · no stuck states"`).

## Alternatives considered

- **Creating a separate `packages/game/animstates` package**: Strongest argument is keeping `animclip` narrowly scoped to single-clip playback. Rejected because `anim3d` already houses both clips and `StateMachine` together, sprite state machines directly orchestrate `animclip.Player` and `animclip.Binder`, and keeping them in `animclip` avoids adding another package to the public API and stability matrix while letting callers import one package for 2D animation.
- **Reusing `game/flow.Machine[string]` with Go closures instead of a YAML expression evaluator**: Strongest argument is zero expression parser code. Rejected because `*.states.yaml` must be plain text that both humans and AI tools can author, diff, and statically validate (`game check` must reject unknown parameters, type mismatches, and unread parameters without compiling Go code).
- **Adding top-level `animator` fields directly to `sceneformat.ObjectDoc`**: Strongest argument is slightly shorter YAML in scenes. Rejected because it would require bumping the scene schema version (`v3`) and duplicating override handling; registering `animator` as a built-in component follows the same pattern as physics components (`body2d`/`collider2d`) and works seamlessly in `version: 1` and `version: 2` scenes.

## Consequences

- **Benefits**: Characters and animated props can define multi-state sprite graphs in plain, diffable, schema-validated YAML; editor preview and game runtime execute the exact same `animclip.StateMachine` on fixed steps; `game check` catches broken transitions, missing clips, and dead parameters with exact `file:line`; `refs` preserves paths across moves; and coding agents can author and test state machines end-to-end through `states_write` and `states_test`.
- **Costs**: `animclip` maintains a small pure-Go boolean/comparison expression parser and static type checker for `when` guards, and `states_test` uses a fixed lightweight platformer kinematic model (`InputDriver`) rather than running full game physics scripts.
- **Verification**: Covered by `animclip` conformance and unit tests (`TestFormatConformance`, `TestKnightStateMachineIdleRunJumpFallRun`, `TestSimulateStateMachineDefaultScript`), `cmd/gameschema` schema generation and `-check`, `refs` scan and move-plan tests, `tooling/assetcheck` diagnostics tests with exact line numbers, `editor` parity and nsgotest UI/macOS screenshot tests (`TestKnightStateMachineIdleRunJumpFallRunMatchesEditorAndGame`, `TestStatesGraphUIAndDriveWithKeysAndScreenshot`), and `editor/editormcp` end-to-end `states_write`/`states_test` tests.
