# Agent Note: Editor full Dark/Light SpecPalette parity, 2D viewport clarity, Command Palette scopes, and Scene Tree quick actions

Status: implemented

## Problem

Although [the Spec light/dark theme](./2026-11-26-editor-spec-light-theme.md) and [Spec design tokens](./2026-11-26-editor-spec-design-tokens.md) established `spec_theme.yaml` and `Editor.SpecPalette(cx)`, nineteen editor UI files still relied on package-level color variables initialized once from `darkSpecPalette` (such as `specBg`, `specPanel`, `specText`, `specFocusRingStyle`, and per-screen tint vars), leaving half of the editor stuck in dark-mode colors when switched to Light appearance. Real macOS screenshot inspection also surfaced concrete UI and workflow defects: `ui.Checkbox` controls in Inspector, Snap settings, Material, and Particle editors set only the accessibility `Label` without visible `Text`; Scene Tree rows clipped the lock button in the 232 px rail when `NEW` and kind tags were present; long paths in First Run step 2 overflowed the Connect card; `viewportCameraCaptionView` did not react to `SetCanvasSize` layout updates and landed behind the top-left overlay legend on first render; unselected non-sprite 2D objects and the Spec dot-grid surround were invisible on the 2D edit canvas; Command Palette (`⌘K`) lacked scene nodes, Settings pages, prefix scopes (`>`, `@`, `#`), recent items, and "Ask the agent" handoff from `docs/design/editor/Palette.dc.html`; and the Scene rail offered neither node filtering nor one-click object/layer creation.

## Decision

Every editor screen now resolves colors reactively through `Editor.SpecPalette(cx)` / `Editor.activeSpecPalette()`, enforced by a new AST guardrail (`TestSpecNoDarkOnlyPackageColorVarsInEditor`), alongside targeted fixes for layout, 2D viewport legibility, Command Palette navigation, Scene Tree productivity, and EN/ZH menu localization.

### Key design choices

- **Zero dark-only package color aliases**: Deleted all package-level `spec*` color and focus-ring variable blocks (`profiler_ui.go`, `start_screen_ui.go`, `states_ui.go`, `focus_regions.go`, `hud_layout_ui.go`, `changes_ui.go`, `playtest_report_ui.go`, `asset_gen_ui.go`, `asset_drawer_ui.go`, `usages_ui.go`, `merge_conflict_ui.go`, `cutscene_ui.go`, `tile_review_ui.go`) and migrated all consumer views and canvas painters to `ed.SpecPalette(cx)` with `p.*.OnFill` / `p.OnTextPrimary` on solid fills and `p.FocusRing(...)` for focus outlines. Only non-UI-chrome fixed-contrast data remains explicit (QR code dark-on-white quiet zone in `build_release_ui.go`, exported agent PNG ink in `sketch_png.go`, and dark game viewport contrast backdrop in `hud_layout.go`). `TestSpecNoDarkOnlyPackageColorVarsInEditor` walks the `pkg/editor` AST and fails on any new package-level `var` referencing `darkSpecPalette` or `lightSpecPalette` outside `spec_theme.go`.
- **Lightweight canvas-size notification (`SubscribeCanvasSize`)**: `Editor.SetCanvasSize` increments `canvasSizeRev` and notifies `canvasSizeListeners` whenever dimensions change without bumping `Editor.Revision`, mirroring `SubscribePointer`. `viewportCameraCaptionView` subscribes to `canvasSizeRev` and offsets its fallback below the overlay legend when `OverlayLegendOpen()` is true.
- **Neutral 2D dot grid and non-sprite markers**: `DrawViewport` draws the Spec 16×16 `ViewportDot` surround as a single dashed-stroke path (`1.2 px` dash every `16 px`, avoiding thousands of per-frame `FillRect` ops) when `!e.playing && !scene.HasBackground`, and draws neutral (`Raised` fill, `TextFaint` stroke, `TextMuted` center dot) markers for visible non-sprite 2D objects in edit mode so empty nodes, prefabs without sprites, and triggers are visible and pickable without ever using semantic overlay legend colors (`TestCameraFrameBoundsAndTileGridUseNeutralSpecTokens`).
- **Command Palette (`⌘K`) scopes, nodes, settings, recent, and Ask the agent**: `palette.go` indexes open-scene objects (`node:<id>`, selecting, switching to Inspector, and framing on pick) and Settings pages (`setting:<page>`), applies prefix scopes (`>`, `@`, `#`) in `filterPaletteItemsWithEditor`, promotes up to 6 recent items (`PaletteRecent`) into the Recent group in `buildPaletteItemsForUI`, and keeps a single stable `ask:` item whose reactive `Trailing` node reads `query.Get()` so typing never rebuilds `base.Command`'s item index; selecting it stages the query in the Agent composer (`SetComposerDraft`) and switches to `RightTabAgent`.
- **Scene Tree quick filter, quick-add `+` menu, and non-clipping rows**: `leftRailSceneView` adds a 28×28 filter toggle (`SceneTreeFilter` / `SetSceneTreeFilterOpen`) and a 28×28 `+` menu (`AddSceneRailObject`, `AddSceneRailLayer`, all undoable through `History`) in `scene-rail-header`. `scenetree.go` sets `Direction: core.Row, FlexGrow: 1, FlexShrink: 1, FlexBasis: 0, MinWidth: 0` across the row wrappers (`ui.ContextMenu`, `dragdrop.Target`, `dragdrop.Source`, `content`) and label text with 18 px eye/lock toggles so names ellipsize cleanly without clipping or collapsing vertical drag hitboxes, and `first_run_ui.go` constrains Connect step text with `FlexGrow: 1, FlexShrink: 1, FlexBasis: 0, MinWidth: 0`.
- **Visible checkbox labels and localized menus**: Added explicit `Text` alongside accessibility `Label` on `ui.Checkbox` controls in `inspector_edit.go`, `inspector_multi.go`, `inspector.go`, `snap.go`, `materials_ui.go`, and `particles_ui.go`, and localized remaining hardcoded English desktop menu strings in `menubar.go` across `locales/en.yaml` and `locales/zh.yaml`.

Related notes: [AI-first main layout](./2026-11-26-editor-ai-first-main-layout.md), [Spec light theme](./2026-11-26-editor-spec-light-theme.md), [Spec design tokens](./2026-11-26-editor-spec-design-tokens.md).

## Alternatives considered

- **Coloring unselected non-sprite 2D markers with `ObjectKindColor` (Accent/Added/Changed/Warning)**: rejected because `TestCameraFrameBoundsAndTileGridUseNeutralSpecTokens` and `Spec.dc.html` reserve semantic legend hues strictly for selection, agent activity, review diffs, and problems; neutral `Raised`/`TextFaint`/`TextMuted` markers keep objects legible while letting semantic overlays stand out unambiguously.
- **Bumping `Editor.Revision()` inside `SetCanvasSize`**: rejected because `DrawViewport` calls `SetCanvasSize` during painting; bumping `Editor.Revision` from `SetCanvasSize` would trigger redundant full-tree UI invalidations and risk draw/layout feedback loops. A dedicated `canvasSizeRev` listener matches `SubscribePointer` and limits updates strictly to layout-dependent overlays.
- **Auto-submitting Command Palette "Ask the agent" prompts immediately**: rejected in favor of staging the prompt in the Agent panel composer (`SetComposerDraft`) and switching to `RightTabAgent`, so the user sees the attached context chips before sending and avoids accidental agent runs from a mistyped search query.

## Consequences

- **Benefits**: 100% of editor screens adapt live to Dark and Light appearances with AST-enforced regression protection; checkboxes, Scene Tree rows, First Run Connect steps, status bar indicators, and the 2D viewport camera caption render cleanly without clipping or missing labels; authors can find/frame scene nodes, open Settings pages, filter the Scene Tree, and add objects/layers directly from the UI.
- **Costs**: Views wrapping inner subtrees in a theme-keyed `core.Dynamic` must keep text-input signals and memos in the outer scope so typing focus survives non-theme revisions; any future editor screen must pass `SpecPalette` rather than declaring package-level color vars.
