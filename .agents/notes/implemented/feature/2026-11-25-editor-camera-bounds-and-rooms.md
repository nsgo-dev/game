# Agent Note: Editor 2D viewport camera bounds handles and side-by-side room map editing

Status: implemented

## Problem

Issue #871 added the Scene Settings inspector and a 2D viewport handle for dragging the scene camera's `(x, y)` position ([scene settings inspector](./2026-11-25-editor-scene-settings-inspector.md)), but two parts of #884 remained YAML-only:

1. **`camera.bounds` visual editing**: `drawCameraFrameOverlay` drew the dashed bounds rectangle, yet authors still had to type raw numbers in the inspector to resize or move it. Resizing `camera.bounds` live in the viewport also faces the same feedback-loop hazard as dragging the camera handle when `View2D` follows the clamped scene camera, and bounds interior hit-testing must not steal pointer clicks on scene objects sitting inside `camera.bounds`.
2. **Metroidvania room maps (`*.rooms.yaml`)**: `packages/game/rooms` defines a versioned, deterministic room-map YAML format (`rooms.Parse`, `rooms.Encode`), but the editor had no way to open a `*.rooms.yaml` beside the scene, draw its rooms over the 2D viewport, create/move/resize/delete rooms with handles snapped to the scene's tile grid, or inspect and edit each room's `id`, `name`, and `transition` with shared undo/redo.

## Decision

- **Shared `RectHandle` geometry and camera bounds drag (`packages/game/editor/scenesettings.go`, `viewport.go`, `view2d.go`)**: `RectHandle` enumerates `RectHandleBody` plus the 8 corner and edge-midpoint handles (`N`, `E`, `S`, `W`, `NE`, `SE`, `SW`, `NW`) with shared canvas-space hit testing (`hitTestWorldRect`), handle drawing (`drawWorldRectHandles`), and edge-clamped/grid-snapped resizing (`applyRectDrag`). When `ShowingSceneSettings()` is true in 2D edit mode (Select or Move tool), `drawCameraFrameOverlay` renders the 8 amber handles on `camera.bounds`, and `BeginCameraBoundsDrag` / `UpdateCameraBoundsDrag` / `EndCameraBoundsDrag` / `CancelCameraBoundsDrag` update `Doc.Camera.Bounds` live while freezing `View2D()` to `startView` so clamping shifts never feed back into `CanvasToWorld`. Resize handles and the perimeter border take precedence over interior objects, while interior body drags yield to scene objects (`HitTest`) and rooms (`HitTestRoom`). Committing records a single `"Resize camera bounds"` or `"Move camera bounds"` `setCameraCmd` on `Editor.History`; Escape, touch cancel, two-finger navigation, Play, Save, Undo/Redo, and selection/tool switches cancel any active drag cleanly.
- **Side-by-side `*.rooms.yaml` state and viewport overlay (`packages/game/editor/rooms.go`, `viewport.go`, `files.go`, `scenefile.go`)**: `Editor` holds an optional `roomMapState` opened beside the scene via `OpenRoomsFile`, `OpenRoomsProjectFile`, `OpenRoomsYAML`, `NewRoomMap`, or from `FilesView` (double-click or Open on `*.rooms.yaml`/`*.rooms.yml`) and the Scene Settings inspector's ROOMS section. `drawRoomsOverlay` renders every room's translucent fill, border, `id`/`name`/transition badge, and 8 resize handles on the selected room over the 2D scene. `HitTestRoom` delegates to `rooms.Map.RoomAt` so overlapping rooms resolve identically to runtime.
- **Tile-grid edge snapping (`RoomGridSize`, `RoomSnapToGrid`, `SetRoomSnapToGrid`)**: Grid snapping defaults to on and automatically discovers the tile grid from the scene's active/first inline tilemap (`TilemapDoc.TileWidth`/`TileHeight`), falling back to any built external Tiled/LDtk map (`BuiltLayer.Map.TileWidth`/`TileHeight`), or an explicit `SetRoomGridSize(w, h)` override. Moving snaps `(x, y)` to the grid keeping size intact; resizing snaps only the dragged edge(s) while keeping the opposite edge fixed and enforcing a minimum size of one tile (or `1` world unit without a grid); drawing a new room in `RoomCreateMode` snaps both corners.
- **Room inspector, shared History, and deterministic saving (`packages/game/editor/inspector_room.go`, `inspector.go`, `commands.go`)**: Selecting a room (`SelectRoom`) clears object/layer/asset selection and switches `InspectorView` to `roomInspectorView`, editing `id` (`SetRoomID`, committed on Enter/Blur), `name` (`SetRoomName`), bounds (`SetRoomRect`), and per-room `transition` (`SetRoomTransition`: Inherit / Cut / Slide / Fade, with duration parsed via Go duration units, easing selector, and CSS fade color). Every room mutation validates against `rooms.Validate` before touching state or `Editor.History` (allowing transient 0-room state only after deleting the last room in memory, while `SaveRoomsYAML` / `rooms.Encode` still requires at least one room). `HasUnsavedChanges()` includes `RoomsDirty()`, `Save()` persists dirty room maps that have a file path or `OnSaveRooms` callback, and `SaveRoomsYAML` delegates directly to `rooms.Encode` so canonical `*.rooms.yaml` files round-trip unchanged byte-for-byte.

## Alternatives considered

- **Store rooms inside `*.scene.yaml` instead of opening `*.rooms.yaml` beside the scene**: Rejected because `packages/game/rooms` already defines a standalone `*.rooms.yaml` format shared with `rooms.Director`, `rooms.FromLDtk`, and `rooms.FromTiledLayer`, and issue #884 explicitly requires opening and saving `*.rooms.yaml` beside the scene with deterministic round-trip output.
- **Use a separate undo stack for room edits**: Rejected because authors move between scene objects, camera bounds, and room rectangles in the same 2D viewport; sharing `Editor.History` makes `Mod+Z` / `Mod+Shift+Z` consistent across all viewport edits and matches the Data Table and Animation editors.
- **Allow interior drags anywhere inside `camera.bounds` to override scene objects**: Rejected because `camera.bounds` normally encloses the entire playable level; yielding interior drags to `HitTest` and `HitTestRoom` while keeping the 8 handles and perimeter border directly draggable preserves normal object and room picking inside the bounds.

## Consequences

- **Benefits**: Authors can visually resize and move `camera.bounds` and author `*.rooms.yaml` room maps directly over their 2D level with tile-grid snapping, live viewport feedback, full inspector editing, single-step Undo/Redo, and byte-for-byte deterministic saves verified against `rooms.Parse`.
- **Costs**: Opening a new scene (`OpenYAML` / `OpenFile`) clears any open room map because room coordinates belong to the scene being edited. Deleting the final room is permitted in-memory so authors can replace it without closing the map, but saving remains refused by `rooms.Encode` until at least one room exists.
- **Verification**: `packages/game/editor/rooms_test.go` exercises camera bounds handle dragging (resize, move, Escape cancel, save/reload round-trip, Undo/Redo, and non-interference with objects inside bounds) and end-to-end room-map editing (opening from YAML and project file browser, tile-grid-snapped create/move/resize, delete via inspector and Delete key, editing `id`/`name`/`transition` in the inspector, `rooms.Parse` validation, and byte-for-byte round-trip preservation on `castle.rooms.yaml`).
