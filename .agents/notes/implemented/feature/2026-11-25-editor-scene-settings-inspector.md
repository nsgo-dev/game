# Agent Note: Editor inspector edits scene settings and camera with 2D viewport handle

Status: implemented

## Problem

A scene's own top-level settings (`name`, `virtualWidth`, `virtualHeight`, `backgroundColor`, and `camera` with `x`, `y`, `zoom`, `rotation`, and optional `bounds`) are part of `sceneformat.SceneDoc`, yet the editor had no setter methods for them and `InspectorView` rendered only "No object selected" whenever nothing was selected (#871). Three constraints shape the implementation beyond wiring form inputs:

1. **Validation before mutation and history**: `sceneformat.Validate` refuses one-sided zero virtual sizes, non-positive zoom or bounds, and malformed CSS colors. Furthermore, `sceneformat.Validate` permits `(0, 0)` as an unset virtual size, whereas the editor must refuse a non-positive virtual size (including `0`) in the status bar without mutating `Doc` or pushing a history step. Bounded `ui.NumberInput` controls (`Min`/`Max`) would silently clamp `0` instead of reporting the refusal.
2. **Default camera initialization and exact undo**: When `Doc.Camera` is `nil`, world-space layers draw with the identity transform, placing `(VirtualWidth/2, VirtualHeight/2)` at the center of the virtual screen. Editing a single camera field (such as `X`, `Zoom`, or enabling `Bounds`) or dragging the camera handle must initialize the new `CameraDoc` at that effective center rather than `(0, 0)`, and Undo must restore `Doc.Camera` to `nil` byte-for-byte.
3. **2D viewport camera-handle drag feedback loop**: The 2D view follows `Doc.Camera` by default ([2D view independent of camera](./2026-11-25-editor-2d-view-independent-of-camera.md)). Updating `Doc.Camera` live while dragging the camera handle would move `View2D` under the cursor and feed back into `CanvasToWorld`, accelerating the drag away from the pointer.

## Decision

- **Undoable scene settings setters (`packages/game/editor/scenesettings.go`)**: `Editor` exposes `SetSceneName`, `SetVirtualSize`, `SetBackground`, `SetCamera`, `SetCameraPosition`, `SetCameraZoom`, `SetCameraRotation`, `SetCameraBounds`, and `ClearCameraBounds`. Each setter rejects edits during Play (`ErrPlaying`), validates a candidate shallow copy of `Doc` with `sceneformat.Validate` (and `SetVirtualSize` additionally rejects `width <= 0 || height <= 0`), returns `nil` on no-op changes without pushing history, and executes a command on `History` that restores exact prior pointers (`nil` `Camera`, `Zoom`, or `Bounds`) on `Undo`.
- **Scene Settings inspector (`packages/game/editor/inspector_scene.go`, `inspector.go`, `scenetree.go`)**: When `SelectedObject()` is `nil` and `Doc != nil`, `inspectorSchemaKey` returns `"scene"` and `InspectorView` renders `sceneInspectorView` (following the same `ed.report` refusal contract established for object fields in [inspector components and sprite](./2026-11-25-editor-inspector-components-sprite.md)). Numeric inputs for virtual size, zoom, and bounds leave `Min`/`Max` unbounded so typing `0` or a negative number reaches the setter and reports the validation error in `Status`, then resets the displayed value from `Doc`. Background color combines NSGo's `ui.ColorWell` + `ui.ColorPicker` (live preview on `OnChange`, single undoable commit on `OnChangeEnd` or popover close) with a direct CSS/hex `ui.Input` and a clear button. `SceneTreeView` checks `selection.Has(cur)` and clears `selection.SetCursor(nil)` alongside `selection.Clear()` when `SelectedID` becomes empty so deselecting an object reliably returns the inspector to Scene Settings instead of re-selecting the stale cursor row.
- **2D viewport camera overlay and handle drag (`packages/game/editor/viewport.go`, `view2d.go`, `scenesettings.go`)**: While `ShowingSceneSettings()` is true in 2D edit mode, `drawCameraFrameOverlay` highlights the camera start view frame and dashed bounds and draws a crosshair + circular handle at `CameraHandleCanvasPos()`. `BeginCameraDrag` captures `startView := e.View2D()`, and `View2D()` returns `startView` while `cameraDrag.active` is true so `CanvasToWorld` stays anchored with zero feedback loop during live drags. `EndCameraDrag` restores `origCamera` before committing one `"Move camera"` command to `History`, and `ViewportView` suppresses `OnPress` only when a drag actually moved the camera so plain clicks still pick objects.

## Alternatives considered

- **Clamp invalid values inside `ui.NumberInput` (`Min`/`Max`)**: Prevents users from typing `0` or negatives, which violates the acceptance requirement that typing a zero width is refused in the status bar and changes nothing. Leaving `Min`/`Max` unset lets `SetVirtualSize`, `SetCameraZoom`, and `SetCameraBounds` enforce one single source of truth via `sceneformat.Validate`.
- **Detach `View2D` permanently (`view2DFree = true`) on camera handle drag**: Breaks the feedback loop, but permanently detaches the 2D view from the camera even if the author never panned or zoomed. Freezing `View2D()` to `startView` only for the duration of the active drag avoids the feedback loop while preserving `View2DFollowsCamera()`.
- **Add new scene format fields (`gravity`, `music`, camera `follows`, `smoothing`) from `Inspector.dc.html` in the same PR**: Rejected because those fields do not exist in `sceneformat` today and require a schema and version change; per issue #871's design comment they belong in a follow-up issue.

## Consequences

- **Benefits**: Scene name, virtual size, background color, and full camera configuration can be authored visually with live viewport feedback, direct 2D handle dragging, exact byte-for-byte YAML round-tripping, and clean Undo/Redo without hand-editing YAML.
- **Costs**: `SetVirtualSize` refuses `(0, 0)` from the editor even though `sceneformat.Validate` permits both-zero unset virtual sizes on hand-authored files; authors who explicitly want omitted virtual dimensions must edit the YAML directly. `ColorWell` previews mutate `Doc.BackgroundColor` transiently while dragging inside the popover and restore before committing on `OnChangeEnd` or close.
- **Verification**: `packages/game/editor/scenesettings_test.go` verifies end-to-end UI edits (name, virtual size, hex input, `ui.ColorWell`/`ui.ColorPicker`, camera x/y/zoom/rotation, toggleable bounds) with byte-for-byte save/reload and full Undo/Redo, status-bar refusals for zero width and other invalid values with no history or document mutation, `ErrPlaying` guards, and 2D viewport camera handle dragging (both camera-following and zoomed free views, nil-camera initialization, undo, and cancel).
