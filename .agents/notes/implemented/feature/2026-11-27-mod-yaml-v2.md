# Agent Note: mod.yaml v2, Per-Mod Discovery Failure Isolation, and ContentFS Overlay

Status: implemented

## Problem

`mod.yaml` version 1 only declared required dependencies and an entry script, so mods could not express soft dependencies, mutual incompatibilities, target platform filters, or content-only packs (sprites, scenes, data tables, and localization tables without TSX host code). In addition, `Manager.DiscoverFS` aborted on the first invalid manifest, missing entry script, incompatible game version, duplicate ID, or dependency error, meaning one broken mod in a folder stopped every healthy sibling mod from loading.

## Decision

`pkg/modding` adds `manifestVersion: 2` (`MinManifestVersion = 1`, `ManifestVersion = 2`) alongside lossless version 1 compatibility, isolates discovery failures per mod in `Manager.DiscoverFS`, and exposes loaded mods' contributed directories through a concurrency-safe, read-only `Manager.ContentFS()` overlay.

### mod.yaml v2 format and version preservation

- `ModManifest` adds `OptionalDependencies`, `Conflicts`, `Platforms`, and `Contributes` (`ModContributes{Assets, Scenes, L10n, DataTables}`), all restricted to `manifestVersion: 2`.
- Version 1 files keep loading unchanged, refuse every v2 key (including empty `platforms: []` or `contributes: {}`), require `entry`, and retain `ManifestVersion == 1` so `EncodeManifest` round-trips existing v1 files byte for byte. Version 2 files require either `entry` or at least one non-empty directory under `contributes`, enabling content-only mods that activate into `StateLoaded` without compiling a TSX sandbox.
- `EncodeManifest` writes canonical 2-space YAML with `dependencies`, `optionalDependencies`, and `conflicts` sorted by ID in byte order and `platforms` formatted as a flow sequence sorted in byte order. A manifest built in Go with `ManifestVersion == 0` encodes as `manifestVersion: 2`.
- `tools/gameschema` publishes `mod.v1.json` (`SchemaURL`) and `mod.v2.json` (`SchemaURLV2`) using `versionField: "manifestVersion"`, keeping v1 strict against v2 fields and requiring `entry` only on v1.
- `ResolveOrder` checks `conflicts` in both directions using the shared SemVer constraint evaluator from [internal/semver](../architecture/2026-11-27-internal-semver-constraints.md) (returning `ErrConflictingMods`), adds topological edges and constraint checks for present `optionalDependencies`, ignores absent `optionalDependencies`, and preserves lexicographic tie-breaking.

### Per-mod discovery failure contract

- `Manager.DiscoverFS` only aborts without modifying the registry when the top-level directory itself cannot be read.
- For every mod subdirectory, manifest read/parse errors, legacy `mod.json`-only directories, `gameVersion` mismatches, unsupported `platforms` (`ErrUnsupportedPlatform`, checked against `ManagerOptions.Platform` or the runtime platform mapping `darwin -> macos` and `js -> web`), missing or escaping `entry` / `contributes` paths (`ErrUnsafePath`), duplicate IDs (failing every mod claiming that ID with `ErrDuplicateMod`), conflicts (failing both sides symmetrically with `ErrConflictingMods`), unsatisfied or failed required dependencies (including transitive dependents, marked with `ErrModFailed`), version-mismatched present optional dependencies, and dependency cycles are recorded individually as `StateFailed` with `Error` and `Dir` on `ModInfo`.
- Absent or discovery-failed optional dependencies never fail their dependents.
- Healthy mods are registered in deterministic topological load order (`m.order`) and returned in `DiscoverFS`'s `[]ModManifest`; failed mods are retained in `m.failed` (and `m.mods[id]` when they have an ID) so `Manager.List()` and `Manager.Info(id)` expose every failure, while `DiscoverFS` returns `errors.Join(errs...)` matching `Manager.LoadAll` and `Workshop.SyncSubscribed`. Calling `Manager.Load(id)` on a discovery-failed mod keeps it `StateFailed` and returns its discovery error.

### Read-only ContentFS overlay and path confinement

- `Manager.ContentFS() fs.FS` exposes an atomic snapshot (`atomic.Pointer[contentSnapshot]`) refreshed on every load, unload, disable, reload, discovery, uninstall, runtime failure, or close transition, so `assets.Manager` worker goroutines can read safely off the engine goroutine without locking against `Manager` mutations.
- Contributed directories are mounted under the four canonical top-level namespaces `assets/`, `scenes/`, `l10n/`, and `datatables/`, stripping each mod's internal directory name (`locales`, `tables`, `art`, etc.) so later loaded mods cleanly override earlier mods per path without cross-category collisions between YAML files.
- `ContentFS` implements `fs.FS`, `fs.StatFS`, and `fs.ReadDirFS` (merging directory listings across loaded layers in sorted order with later mods winning on duplicate names).
- Every path is validated against `fs.ValidPath` and backslashes, and every symlink component is resolved via `io/fs.ReadLinkFS` (implemented by `os.DirFS`, `fs.Sub`, and `fstest.MapFS`) against the mod's own root directory with a 40-hop loop limit, refusing absolute targets, relative escapes, and loops with `ErrUnsafePath` both at discovery/install/reload time and on read (matching [Steam Workshop sync](2026-11-24-modding-steam-workshop.md)).

## Alternatives considered

- **Merging all four `contributes` directories flat into `ContentFS()` root `.`**: Avoids calling `fs.Sub(mgr.ContentFS(), "assets")` when passing directly to `assets.WithFS`. Rejected because `scenes`, `l10n`, and `datatables` all use `.yaml` files (such as `en.yaml` vs `enemies.yaml`), so flattening them into one directory causes filename collisions and prevents hosts from walking a single category such as `l10n/` without parsing unrelated YAML files.
- **Returning `nil` error from `DiscoverFS` when per-mod failures occur**: Lets naive callers ignore `err` and still load healthy mods. Rejected because it breaks existing `DiscoverFS` error contracts (including `*loaderr.Error` reporting on bad manifests, duplicates, and dependency errors) and diverges from `Manager.LoadAll` and `Workshop.SyncSubscribed`, both of which isolate per-mod failures while returning a joined error.
- **Failing only the second mod on a duplicate ID or conflict**: Lets one of the two mods keep loading. Rejected because which mod wins would depend on directory naming or which side declared the conflict, violating symmetric conflict refusal and hiding accidental duplicate installs.

## Consequences

- **Benefits**: Existing v1 `mod.yaml` files remain byte-for-byte compatible; mod authors can publish content-only packs, platform-scoped mods, soft integrations, and explicit incompatibilities; one broken mod no longer disables an entire mods directory; hosts get a race-free, stdlib-conformant (`fstest.TestFS`) read-only overlay with defense-in-depth symlink confinement.
- **Costs**: `ModManifest` built in Go with `ManifestVersion == 0` now encodes as `manifestVersion: 2` rather than `1` (explicit `ManifestVersion: 1` still encodes as `1`); hosts passing `Manager.ContentFS()` to `assets.WithFS` for bare `"asset:<rel>"` URIs take `fs.Sub(mgr.ContentFS(), "assets")`; `DiscoverFS` callers that want to continue loading healthy mods when individual mods fail inspect the returned `[]ModManifest` and `Manager.List()` rather than returning immediately on a non-nil `DiscoverFS` error.
