# Agent Note: Editor Object Copy, Paste, Duplicate and Group

Status: implemented

## Problem

The scene editor could place, reparent, and delete objects, and had a minimal `DuplicateObject` helper that cloned one object onto its layer without offsetting it or copying internal connections. Authors could not copy or cut objects (with children, components, properties, and internal connections) onto the system clipboard as valid scene YAML, paste them into another opened scene, duplicate subtrees with rewritten internal connections in one undo step, or group and ungroup selections while preserving world transforms.

Meanwhile, `CmdCopyTileRegion`, `CmdCutTileRegion`, and `CmdPasteTileRegion` already bound `mod+c`, `mod+x`, and `mod+v` in the unified command registry (see [editor-tile-brushes](./2026-11-25-editor-tile-brushes.md) and [editor-shortcuts-menu-palette](./2026-11-25-editor-shortcuts-menu-palette.md)), and the registry forbids duplicate shortcuts across commands.

## Decision

Object clipboard, duplicate, and group operations live in `packages/game/editor/clipboard_group.go` alongside multi-selection (`Editor.SelectedIDs`, `SelectObjects`, `ToggleSelectObject`, `IsObjectSelected`) and unified contextual edit commands:

- **Scene-format YAML clipboard**: `CopyObjects` and `CutObjects` normalize selected roots (deduplicating and dropping descendants of already-selected ancestors), build a standalone `sceneformat.SceneDoc` (`Version: sceneformat.CurrentVersion`) containing the roots, their children, internal connections whose endpoints both belong to the copied subtrees, and matching `SceneDoc.Overrides` when the source scene inherits, and write canonical `sceneformat.Encode` YAML to `Editor.WriteClipboard` or `core.Scope.SetClipboard` (with an in-memory fallback when headless).
- **Validated single-step paste and duplicate**: `PasteYAMLWith` parses clipboard YAML via `sceneformat.ParseWith`, allocates fresh unique IDs only where original IDs are already taken in the target scene, rewrites internal connections and scene overrides (including instanced `"id/child"` prefixes), clears `Camera.Current` on pasted copies if the target scene already has a current 3D camera, places roots at the hovered viewport pointer (`SetViewportPointer2D`/`SetViewportPointer3D`) or with a cascading offset when original IDs are taken, validates the full candidate scene (`Validate`, `ValidateComponents`, `ValidateConnections`, `ValidatePhysicsLayers`, and `Resolve` for instanced scenes), and commits in one `pasteObjectsCmd` history step. Unparseable or invalid YAML is refused in `Editor.Status` without mutating `Doc` or `History`. `DuplicateObjects` reuses the same pipeline next to the originals under their existing parent without touching the system clipboard.
- **Contextual `mod+c` / `mod+x` / `mod+v` without shortcut clashes**: `CmdCopy`, `CmdCut`, and `CmdPaste` own `mod+c`, `mod+x`, and `mod+v` in the command registry, dispatching to tile region copy/cut/paste when a 2D tile tool has a tile selection or active tile clipboard (`lastClipboardKind == clipboardTile`) and to object copy/cut/paste otherwise. `CmdCopyTileRegion`, `CmdCutTileRegion`, and `CmdPasteTileRegion` stay registered without duplicate shortcuts for tile palette buttons, menus, and direct command invocation. `CmdPasteInto` (`mod+shift+v`), `CmdGroup` (`mod+g`), and `CmdUngroup` (`mod+shift+g`) are exposed in the Edit menu, Scene Tree context menu, and Command Palette without expanding the 2D top toolbar.
- **World-transform-preserving Group and Ungroup**: `GroupObjects` creates a new empty parent at the mean 2D/3D world centre of the normalized selected roots and moves each root under it using `keepWorldTransform` in one `groupObjectsCmd` step. `UngroupObject` lifts direct children into the parent's slot via `keepWorldTransform` in one `ungroupObjectCmd` step, removing empty unconnected group containers while leaving non-empty parents intact.

## Alternatives considered

1. **Custom clipboard YAML envelope instead of `sceneformat.SceneDoc`**: A custom wrapper such as `clipboard: true` with bare `objects` could avoid `layers`, but would not be valid scene-format YAML, could not be pasted into a text editor with the scene JSON schema, and would require a separate parser and validator. Using `sceneformat.SceneDoc` reuses `sceneformat.ParseWith` and `sceneformat.Encode` verbatim.
2. **Keeping separate shortcuts for tile clipboard and object clipboard**: Assigning alternative chords (such as `mod+alt+c`) to either tile regions or objects would violate standard desktop muscle memory and break existing `TestTileBrushesMountedUIEscapeCancelAndClipboard` assertions on `meta+c` / `meta+v`. Contextual dispatch in `CmdCopy`/`CmdCut`/`CmdPaste` preserves zero shortcut clashes and keeps both workflows natural.
3. **Adding Copy/Paste/Group buttons to the 2D top toolbar**: Putting additional buttons in `editor-toolbar` risks wrapping the bar beyond two rows at `1120x680` and crowding the viewport. Exposing the actions in the Edit menu, Scene Tree context menu, Command Palette, and keyboard shortcuts keeps the toolbar compact.

## Consequences

- **Benefits**: Objects with deep hierarchies, components, properties, instanced-scene overrides, and internal connections move cleanly across scenes or external text editors as plain text YAML; every copy/cut/paste/duplicate/group/ungroup edit is atomic in `History` with byte-for-byte Undo; built-in commands remain collision-free across macOS and Windows/Linux.
- **Costs**: `Editor.DuplicateObject` now offsets the duplicate next to the original (`+16, +16` in 2D, `+1, 0, 0` in 3D) instead of stacking it at identical coordinates, so callers expecting zero-offset copies must pass explicit `PasteOptions{Offset: &[2]float32{0, 0}}` or inspect the offset coordinates. `Paste` stays enabled whenever editing so system-clipboard content from external apps or other scenes can always be pasted and validated on demand.
