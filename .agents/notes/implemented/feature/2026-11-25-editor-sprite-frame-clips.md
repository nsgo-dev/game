# Agent Note: Discrete sprite.frame flipbook tracks in animation clips and the editor

Status: implemented

## Problem

Animation clips (`resource.Animation`, played by `animclip.Player` and authored in `editor`) previously keyed only numeric and boolean properties (`resource.Key{Time, Value, Interp}`). The most common 2D animation — a flipbook walk cycle stepping through atlas frame names — could not be authored, saved in a clip resource, or previewed in the editor, and Aseprite frame tags loaded only into runtime `sprite.Animation` values without reaching scenes or clip files (#881). Adding `sprite.frame` tracks affects four contracts across packages:

1. `resource.Key` is shared with `resource.Curve` and omits neither `time` nor `value` on save (`value: 0` is explicit in canonical YAML).
2. `animclip.Binder` is an exported function type `func(target string, p Property) (func(float64), error)` used by `BindScene`, `BindDoc` and custom game binders.
3. `sceneformat.BuiltObject.Sync` previously copied transform, origin, flip and alpha onto `BuiltObject.Sprite`, not `Sprite.Frame`.
4. Clips created from Aseprite tags must match each tag's exact frame order (including reverse, ping-pong and repeat passes), millisecond durations and loop flag while round-tripping byte-for-byte through YAML.

## Decision

- **Separate `Frames []FrameKey` field on `resource.Track`**: a `Track` sets either `Keys` (`yaml:"keys,omitempty"`) or `Frames` (`yaml:"frames,omitempty"`), never both. `FrameKey` carries only `time` and `frame` (non-empty string), so `yaml.Decoder.KnownFields(true)` refuses `value` or `interp` on discrete frame keys and existing `Curve` and numeric `Animation` files round-trip with zero byte changes. `Track.IsFrameTrack`, `Track.EvalFrame` and `Animation.SampleFrames` expose frame evaluation while `Animation.Sample` skips frame tracks.
- **`animclip.KindFrame` and `Property.Frames`**: `sprite.frame` (`PropertySpriteFrame`) is a built-in object property (`KindFrame`) checked before component lookup so it works without a `ComponentRegistry`. When `NewPlayer` builds a `KindFrame` track, it populates `Property.Frames` with the track's frame names in key order and drives a stepped `tween.Timeline` over key indices (`0..len(Frames)-1`). `BindScene` pre-resolves every frame against `BuiltObject.Atlas.Frames` at `NewPlayer` time (failing fast on missing frames and avoiding per-step map lookups), updates both `bo.Doc.Sprite.Frame` and `bo.Sprite.Frame`, and `BuiltObject.Sync` also copies `bo.Atlas.Frames[od.Sprite.Frame]` onto `bo.Sprite.Frame` so concurrent transform tracks never leave the sprite frame out of sync. Custom binders map indices via `p.Frame(v)` without changing the `Binder` signature.
- **Flipbook constructors in `animclip`**: `FromSpriteAnimation`, `FromAsepriteTag` and `FromFrames` build validated `sprite.frame` clips. `FromSpriteAnimation` accumulates exact `time.Duration` sums before converting each key's start time and `Length` to `float32` seconds, so `animclip.Seconds` reproduces each Aseprite tag's millisecond durations without drift.
- **Editor authoring, thumbnails and retiming**: `Editor` adds undoable `KeySpriteFrame`, `SetKeyFrame`, `SetFrameDuration`, `NewClipFromAsepriteTag` and `NewClipFromFrames`, plus read helpers `FrameDuration`, `ClipTargetFrames`, `ClipTargetAsepriteTags` and `ClipFrameEntry`. `KeyProperty`, `MoveKey`, `DeleteKey` and `SelectedClipKey` handle both numeric and frame tracks. `AnimationPanelView` shows a frame picker when `sprite.frame` is selected, renders atlas frame thumbnails spanning each key's duration on the `sprite.frame` timeline lane, swaps the key editor to frame picker + `-10ms`/`+10ms` duration controls for discrete frame keys, and exposes Aseprite tag and fixed-FPS frame-run clip creation.

## Alternatives considered

- **Adding a `Frame string` field directly to `resource.Key` (or making `Value` polymorphic)**: keeps a single `keys:` list in YAML. Rejected because `resource.Key` is shared with `resource.Curve` and `Value float32` cannot gain `omitempty` without dropping `value: 0` from existing canonical `Curve` and `Animation` fixtures, breaking byte-for-byte round-trips; a polymorphic `Value` would also break Go callers reading `Key.Value` as `float32`.
- **Adding a separate `FrameBinder` parameter or changing `animclip.NewPlayer`'s signature**: makes frame binding explicit as `func(string)` in the type signature. Rejected because it breaks existing `animclip.NewPlayer(clip, reg, animclip.BindScene(built, "hero"))` call sites and custom binders; carrying the track's frame table on `Property.Frames` with `Property.Frame(v)` keeps `NewPlayer` and `Binder` backward-compatible while allowing up-front frame validation and zero-allocation playback in `BindScene`.
- **Storing frame clips in a new multi-clip `.clips.yaml` format**: matches the multi-clip grouping shown on screen 1 of `docs/design/editor/Animation.dc.html`. Deferred because issue #881 targets single-clip `resource.Animation` files played by `animclip` and explicitly allows keeping one animation resource per clip.

## Consequences

- **Benefits**: 2D flipbook animations key, preview through `animclip`, import from Aseprite tags or frame runs, and round-trip deterministically in plain YAML with zero breaking changes to existing resource files, `animclip` callers, or `resource.Curve`.
- **Costs**: `Property.Frames` is only populated while `NewPlayer` binds a track (nil from `Lookup` and `Properties`). `SetFrameDuration` shifts subsequent frame keys on the same track and adjusts clip length, leaving keys on other tracks at their original timestamps.
- **Verification**: `packages/game/resource/resource_test.go` and `conformance_test.go` verify `testdata/hero_walk.animation.yaml`, `docs/{en,zh}/formats.md` examples, rejection of mixed/empty/unknown fields, and `SampleFrames`. `packages/game/animclip/flipbook_test.go` verifies `FromAsepriteTag` across all four tags in `sprite/testdata/aseprite-hash.json` against `sprite.Animation` step-by-step, `FromFrames`, `BindScene`, `BindDoc`, and `BuiltObject.Sync`. `packages/game/editor/animation_sprite_test.go` drives four-frame keying through the UI frame picker, verifies timeline thumbnails, `-10ms`/`+10ms` retiming, Aseprite tag and fixed-FPS creation, full Undo/Redo, byte-for-byte YAML round-trip, and frame-by-frame agreement between editor preview and game playback through `animclip`.
