# Agent Note: Image-collection tilesets, tile objects, object templates, text objects, and layer tints in game/tilemap

Status: implemented

## Problem

Tiled maps commonly place props, trees, and decorations as tile objects drawn from image-collection tilesets (one image per tile with independent sizes or sub-rectangles) and share reusable entity setups through external `.tx`/`.tj` object templates (#849). Previously `game/tilemap` had no per-tile image table on `Tileset`, parsed `ObjectTile` entries without ever drawing them, dropped template references and `<text>` elements, ignored tileset `tileoffset` and `objectalignment`, and discarded layer `tintcolor`. Extending the `Stable` `game/tilemap` package must keep full TMX/TMJ and TSX/TSJ equivalence (building on [TMX/TSX loading](2026-11-25-tilemap-tmx-tsx-and-encoded-data.md)), preserve `YSort` zero-allocation behavior ([per-layer Y-sorting](2026-11-25-tilemap-ysort-with-sprites.md)), avoid breaking `VisitLayers` or `TilesetLoader` callers, and stay compact for the `cmd/wasmprobe` WebAssembly size budget.

## Decision

Extend `tilemap`'s data model, Tiled loader (`tiled.go`, `tmx.go`), and drawing pipeline (`tilemap.go`, `projection.go`, `ysort.go`, `cache.go`, `shapes.go`) together with `gametest.RenderOps` tint support (`gametest/golden.go`):

- **Image-collection tilesets (`Tileset.TileImages`)**: Store per-tile images in `TileImages map[uint32]TileImage` (keyed by sparse 0-based local tile ID) with `Image`, `X`, `Y`, `Width`, and `Height`, supporting both full-image tiles and Tiled 1.9+ sub-rectangles and resolving relative image paths against external tilesets' directories. `Tileset.tileSource`, `Tilemap.TileBox`, `Tilemap.TileShapes`, `maxTilePadding`, `CacheStaticLayer`, `CacheStaticChunk`, and `YSortTile` (`frameLocalID`) all honor `TileImages` without allocating per frame.
- **Tileset `tileoffset` and `objectalignment`**: Parse `<tileoffset>` / `"tileoffset"` into `Tileset.TileOffsetX`/`TileOffsetY` and `objectalignment` into `Tileset.ObjectAlignment` (`ObjectAlignmentUnspecified` defaults to `BottomLeft` on orthogonal/staggered/hexagonal maps and `Bottom` on isometric maps, matching Tiled). All tile-layer renderers and `DrawObjectLayer` apply `TileOffsetX`/`TileOffsetY` and expand camera culling bounds via `maxTilePadding`.
- **Interleaved tile-object drawing (`Tilemap.DrawObjectLayer`)**: Record `layerKindObject` in `Tilemap.layerOrder` while keeping `VisitLayers`'s existing 2-argument signature intact through an internal `visitAllLayers` helper. `Tilemap.Draw` interleaves tile layers, image layers, and object layers in Tiled's layer order. `DrawObjectLayer` draws visible `ObjectTile` objects applying layer `Visible`, `Opacity`, `TintColor`, `OffsetX`/`OffsetY`, `ParallaxX`/`ParallaxY`, object `Width`/`Height`, clockwise `Rotation` about the aligned anchor point, GID flip flags (`FlipHorizontal`, `FlipVertical`, `FlipDiagonal`), `tileoffset`, and `objectalignment`, with exact transformed-corner AABB camera frustum culling.
- **Object templates (`.tx` and `.tj`)**: Add `TilesetLoader.LoadTemplate func(source string) ([]byte, error)`. Both XML `.tx` (`parseTX` sharing `parseXMLRoot`/`parseXMLTileset`/`parseXMLObject`) and JSON `.tj` parse into `tiledTemplate`, are cached per `LoadTiled` call in a compact slice (avoiding an extra runtime map type in WASM), merge template fields/shape/properties with instance overrides without mutating cached maps, and remap template-local GIDs onto the map's tilesets (reusing an already-loaded external tileset when the canonical path matches, or appending a new tileset at `m.nextFirstGID()`). Errors in a template name the template file, line, field, and fix hint.
- **Text objects as data (`ObjectText` / `TextObject`)**: Parse `<text>` / `"text"` objects into `Object.Text *TextObject` (pointer field so non-text objects remain small) with Tiled's defaults (`FontFamily: "sans-serif"`, `PixelSize: 16`, `Color: core.RGB(0x000000)`, `Kerning: true`, `HAlign: "left"`, `VAlign: "top"`).
- **Layer `tintcolor`**: Parse `tintcolor` on tile, image, object, and group layers, multiplying parent group tints channel-wise into child layers (`TileLayer`/`ImageLayer`/`ObjectLayer` `TintColor` + `Tinted`, preserving `#00000000` transparent black distinctly from untinted), and draw tinted layers via `core.Drawing.DrawTintedImageFrom`/`DrawTintedImageIn`/`DrawTintedImage` (skipping zero-alpha tints). `YSortDrawer` flushes and draws individually when a layer is tinted or switches collection tile images. `gametest.RenderOps` applies `op.Tinted`/`op.Color` (including zero-alpha tints) matching `mcp/screenshot.go` so golden tests render tinted maps accurately.
- **Cross-architecture determinism & compact loader structs**: `DrawObjectLayer` guards non-finite rotations/coordinates and breaks arm64 FMA contractions with explicit `float32`/`float64` conversions; XML-only loader metadata sits behind nilable pointers (`xmlLayerMeta`, `xmlChunkMeta`, `xmlPropMeta`) so `.tmj` loading stays well within `BenchmarkLoadTiled` memory budgets, and `loaderr.LocateJSON`'s `jsonFieldPath` uses `walkJSONOnly` so `wasmprobe` does not link `go.yaml.in/yaml/v3`.

## Alternatives considered

- **Flattening image-collection tilesets into a `[]sprite.Frame` slice**: Rejected because image-collection tilesets have one independent `core.ImageSource` per tile (not a shared atlas texture) and often have sparse local tile IDs after tiles are deleted in Tiled; a `map[uint32]TileImage` models both naturally with zero empty-slot waste.
- **Changing `Tilemap.VisitLayers` to add an `*ObjectLayer` parameter**: Rejected because `game/tilemap` is a `Stable` package and `game/scene` (`scene/depth.go`) already depends on `VisitLayers(func(*TileLayer, *ImageLayer))`. Keeping `VisitLayers` unchanged and delegating both `VisitLayers` and `Draw` to internal `visitAllLayers` preserves full API compatibility.
- **Caching templates in `map[string]loadedTemplate` and deduplicating external tilesets via an unexported `Tileset.source` field**: Rejected because storing `source` on `Tileset` would break TMX/TMJ `reflect.DeepEqual` equivalence (`.tsx` vs `.tsj` filenames), and a small slice in `tiledLoadCtx` avoids generating an extra Go map type descriptor in WASM while keeping zero extra allocations on maps without templates.

## Consequences

- **Benefits**:
  - Maps authored in Tiled using image-collection tilesets, rotated/flipped/scaled tile objects, `.tx`/`.tj` templates, text objects, `tileoffset`, `objectalignment`, and `tintcolor` load identically from `.tmj`/`.tsj`/`.tj` and `.tmx`/`.tsx`/`.tx` and render accurately through `Tilemap.Draw`.
  - Golden rendering test (`TestCollectionTileObjectsAndTemplatesGolden`) and mathematical pixel probes verify collection tilesets, sub-rectangles, flips, rotations, template resolution, layer tinting, and hidden-object skipping.
  - Shared XML/tile-data helpers (`parseXMLRoot`, `parseXMLImageElem`, `appendXMLProps`, `decodeTileGridData`, `drawPlacedTile`) keep code duplication and WASM growth modest without adding any third-party dependency or `encoding/xml`.
- **Costs**:
  - `scene.Layer` with `SortY` on a tilemap that combines Y-sorted tile layers with tile-object layers still expands only tile and image layers via `VisitLayers`; maps without Y-sorted tile layers draw object layers normally through `Tilemap.Draw`.
  - Text objects are loaded as structured data (`Object.Text`) rather than rasterized directly by `Tilemap.Draw`, leaving font selection and text rendering to the game's `game/text` pipeline.
