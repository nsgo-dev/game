# Agent Note: BasisLZ/ETC1S KTX2 decoder, full CPU ASTC 4x4 LDR decoder, and reference-encoder fixtures

Status: implemented

## Problem

[KTX2 UASTC transcoding and compressed formats in LoadKTX2](2026-11-24-ktx2-compressed-gpu-textures.md) (#685) left three gaps tracked by #750:

1. `tooling/ktx2` and `render3d.LoadKTX2` refused BasisLZ/ETC1S KTX2 files, even though ETC1S is `basisu`'s default mode and the common payload in `KHR_texture_basisu` glTF assets.
2. The CPU ASTC 4x4 decoder only handled the single-partition, single-plane, 8-bit CEM 8/12 blocks written by `tooling/ktx2`'s own encoder, so `astcenc`-encoded ASTC 4x4 files failed to load on devices without hardware ASTC.
3. No `.ktx2` files written by reference encoders (`basisu`, `astcenc`) were checked in to verify the UASTC, ETC1S, BC7, and ASTC 4x4 decoders against reference decoder outputs.

## Decision

Extend `tooling/ktx2` and `render3d.LoadKTX2` in pure Go (no C, no cgo, no third-party modules) while keeping the existing public API surface unchanged:

- **BasisLZ/ETC1S decoder (`packages/game/tooling/ktx2/etc1s.go`)**:
  - `ktx2.Decode` eagerly parses and validates the BasisLZ Supercompression Global Data (SGD) header, per-level `ImageDesc` entries, the four global slice Huffman tables (`endpointPred`, `deltaEndpoint`, `selector`, `selectorHistoryRLE`) plus `selectorHistoryBufSize`, the delta-coded 5-bit RGB/grayscale color5 + intensity endpoint codebook, and the raw or XOR-delta Huffman selector codebook.
  - Per-level RGB slices and optional alpha slices (decoding alpha from the green channel per Khronos Data Format Specification §22) are decoded using the 2x2 block-quad predictor state, approximate move-to-front selector history buffer, and selector RLE runs into RGBA8 pixels.
  - `Texture.DecodeLevelRGBA` and `Texture.Transcode` decode ETC1S levels on demand using the cached parsed SGD and re-encode into any concrete target format (BC7, BC1, BC3, ETC2 RGB8/RGBA8, ASTC 4x4, UASTC, or RGBA8).
  - `render3d.LoadKTX2` routes both `FormatUASTC` and `FormatETC1S` through the same device-aware `ktx2UniversalTargets` table when the base dimensions are multiples of 4, falling back to RGBA8 otherwise or when `ForceRGBA8` is set.
  - Unsupported BasisLZ features (video P-frames with `imageFlags & 2`, legacy global/hybrid selector codebooks) return explicit errors rather than silently misdecoding.
- **Full CPU ASTC 4x4 LDR decoder (`packages/game/tooling/ktx2/astc.go`)**:
  - Decodes every valid Khronos ASTC 4x4 LDR block: 2D LDR void-extent blocks (with reserved-bit and coordinate validation), all valid 11-bit 2D block modes for 4x4 footprints (`wx, wy <= 4`, `24 <= weightBits <= 96`), Bounded Integer Sequence Encoding (BISE: trits, quints, and bits) for both reverse-bit weight streams and color endpoints, bilinear weight-grid infill for decimated grids, 1–4 partitions via the exact ASTC `hash52`/`select_partition` hash, dual-plane Color Component Selection (`CCS`), and all 10 LDR Color Endpoint Modes (`0, 1, 4, 5, 6, 8, 9, 10, 12, 13`).
  - HDR void-extent blocks and HDR CEMs (`2, 3, 7, 11, 14, 15`), illegal block modes, and 4-partition dual-plane combinations return explicit errors.
- **Reference-encoder fixtures (`packages/game/tooling/ktx2/testdata/ref/`)**:
  - Small 32x32 (and one 16x16) `.ktx2` files and expected unpacked `.png` images generated by `basisu` v2.50.0 (ETC1S opaque/alpha sRGB/linear, UASTC opaque/alpha sRGB and Zstandard-supercompressed linear, multi-mode `bc7e_scalar` BC7) and `astcenc` v6.0.0 (multi-partition, dual-plane, BISE-coded linear and sRGB ASTC 4x4) are checked in (~35 KB total payload) so `go tool nsgo test` verifies all four decoders without requiring external encoders.

## Alternatives considered

### Direct ETC1S-to-ETC2 / BC1 / BC7 / ASTC bit-level transcoding

Avoids a decode-to-RGBA + re-encode pass and preserves exact ETC1S bits on ETC2 devices, but requires maintaining four separate ETC1S transcoder tables and code paths (such as `basisu`'s lookup tables for BC1, BC7 mode 5, and ASTC). Decoding ETC1S to RGBA8 and feeding the existing block encoders matches how `tooling/ktx2` already transcodes UASTC, keeps the codebase compact, and reuses the tested encoders for every target.

### Lookup tables vs. closed-form formulas for ASTC BISE trits, quints, and color unquantization

Embedding the full `trits_of_integer[256][5]`, `quints_of_integer[128][3]`, `quant_mode_table[10][128]`, and 17 `color_scrambled_pquant_to_uquant` tables would add ~15 KB of static data. Implementing the Khronos ASTC specification's bit-level formulas keeps `astc.go` small and self-contained; every formula was cross-checked exhaustively against `astcenc`'s reference tables (0 mismatches across all 256 trit codes, all 128 quint codes, and all 17 color quantization ranges) and verified against `astcenc`-encoded fixtures.

### Lazy SGD parsing only inside `DecodeLevelRGBA`

Leaving `ktx2.Decode` to accept arbitrary bytes in `SGD` for BasisLZ files would delay malformed-container detection until pixel decode or transcode. Parsing and validating the BasisLZ SGD in `ktx2.Decode` matches how Zstandard and ZLIB supercompression are validated eagerly in `ktx2.Decode` and ensures `render3d.LoadKTX2` fails fast with `ErrInvalidTexture`.

## Consequences

- `render3d.LoadKTX2` now loads `basisu`'s default BasisLZ/ETC1S `.ktx2` textures (opaque and alpha, sRGB and linear, with mipmaps) across BC, ETC2, ASTC, and uncompressed GPU profiles.
- `astcenc`-encoded ASTC 4x4 LDR `.ktx2` files (including multi-partition, dual-plane, and BISE-coded blocks) now decode accurately on devices without hardware ASTC.
- ETC1S, BC7, and sRGB ASTC 4x4 decoders match reference `basisu`/`astcenc` outputs bit-for-bit (`0` channel delta); linear ASTC 4x4 and UASTC match within `±1/255` (due to integer `>> 8` vs. reference FP16 float-to-UNORM8 rounding).
- ETC1S encoding (`ktx2.Encode(..., FormatETC1S)`) remains unsupported; `ktx2.Encode` still recommends `FormatUASTC` or direct block formats.
