# Agent Note: Liveops local re-engagement reminders and deferred remote push

Status: implemented

## Problem

`pkg/online/liveops` covers crash reports, consent-gated analytics, cloud saves, and in-app purchases, but had no re-engagement mechanism to bring players back to a game. Every game otherwise has to reimplement notification scheduling, permission prompt timing, quiet hours, player opt-out persistence, and cancel-or-reschedule logic when the app returns to the foreground. Meanwhile, NSGo v0.3.4 ships scheduled local notifications (`core.Scope.ShowNotification` with `At` and `Repeat`, gated by `core.Env.CanScheduleNotifications`), whereas NSGo's remote push API is still an unimplemented design (`nsgo-dev/nsgo#59`) with five unresolved design decisions (`nsgo-dev/nsgo#1323`).

## Decision

`pkg/online/liveops` ships local re-engagement reminders (`liveops.Reminders`) directly over NSGo's `core.Scope.ShowNotification`, and explicitly defers remote push (`liveops.Push`) until `nsgo-dev/nsgo#59` lands and `nsgo-dev/nsgo#1323` settles its API decisions.

- **Permission timing**: `NewReminders` never queries or requests notification permission at launch (on macOS, even checking `NotificationPermission` touches `UNUserNotificationCenter` and alters Dock badge behavior). Permission is requested only when the game first calls `Schedule` / `ScheduleWith` (while reminders are enabled and `CanScheduleNotifications()` is true) or an explicit `RequestPermission`. Concurrent callers share a single permission request. Automatic foreground reconciliation and `SetQuietHours` deferral call `ShowNotification` directly without prompting, so revoked OS permissions degrade silently.
- **Player setting and quiet hours**: `Reminders` persists the player's enabled toggle (`<storageKey>.enabled`), custom quiet-hours window (`<storageKey>.quiet`, storing `"HH:MM-HH:MM"` or `"off"` so turning off quiet hours does not revert to YAML defaults across restarts), and sorted comma-separated active reminder IDs (`<storageKey>.scheduled`) as plain text in `core.Storage`. Disabling reminders immediately cancels all reminders (failing closed even if storage fails) and prevents subsequent `Schedule` calls from prompting. `QuietHours` models a daily local-time window `[Start, End)` (including overnight ranges where `Start > End`), deferring any fire time inside the window to `End`.
- **Foreground reconciliation**: `Reminders` tracks `cx.Env().Lifecycle()` via `cx.Effect` and reconciles active reminders at launch (when active) and whenever the app transitions from non-active to `LifecycleActive`, applying each reminder's `onOpen` policy (`cancel` by default, `reschedule` from the new `WallTime()`, or `keep`).
- **Namespace isolation and press routing**: All reminder notifications are prefixed with `DefaultReminderPrefix` (`"liveops.reminder:"`) so `CancelAll` closes only tracked and declared reminder IDs instead of calling `cx.CloseNotifications()`, leaving unrelated app notifications untouched. `OnNotificationPress` strips the prefix and delivers a `ReminderPress{ID}` event to `RemindersOptions.OnPress`, establishing the event type that a future remote push wrapper can feed into.
- **Remote push deferred**: No `liveops.Push` type or placeholder stub is exported. Package docs (`pkg/online/liveops/doc.go`) and bilingual guides (`docs/en/liveops.md`, `docs/zh/liveops.md`) state that remote push is unavailable everywhere while `nsgo-dev/nsgo#59` and `nsgo-dev/nsgo#1323` remain open.

## Reminder file format

Reminders are declared in a versioned YAML file (`reminders.yaml`, `RemindersVersion = 1`) with published JSON Schema `https://game.nsgo.dev/schemas/reminders.v1.json` (`apps/website/public/schemas/reminders.v1.json`, generated by `tools/gameschema` and checked in CI):

- Top-level fields: required `version: 1`, optional `quietHours` (`start` and `end` as distinct 24-hour `"HH:MM"` strings), and optional `reminders` list.
- Each `ReminderDef` holds a unique `id` (`[A-Za-z0-9._-]`, 1–128 bytes), required localization key `title`, optional localization key `body`, mutually exclusive schedule trigger `delay` (positive Go duration string) or `at` (24-hour `"HH:MM"` local wall-clock time), optional `weekday` (`sunday`..`saturday`, only with `at` and never with `repeat: daily`), optional `repeat` (`daily` or `weekly`), optional `onOpen` (`cancel`, `reschedule`, or `keep`), and optional `silent`.
- `ParseReminders` and `LoadRemindersFS` refuse unknown keys, duplicate keys, trailing YAML documents, YAML anchors/aliases/merge keys, non-canonical version scalars, and unsupported versions with `*loaderr.Error` line information. `EncodeReminders` writes `RemindersSchemaComment` followed by deterministic 2-space YAML that round-trips unchanged under `internal/formattest`.

## Alternatives considered

### Speculative `liveops.Push` stub ahead of upstream NSGo

Shipping an exported `liveops.Push` wrapper returning `ErrUnsupported` everywhere would reserve symbol names early. Rejected because `nsgo-dev/nsgo#1323` has not settled token lifecycle, payload delivery shape, or platform scope; guessing the signature now would either lock in the wrong game-layer API or force a breaking change once NSGo lands `#59`.

### Using `cx.CloseNotifications()` in `CancelAll`

Calling `cx.CloseNotifications()` is one line and clears every notification even if a reminder ID was removed from `reminders.yaml` between versions. Rejected because `CloseNotifications` wipes every notification shown or scheduled by the entire app, including unrelated chat or system alerts. Prefix-scoped cancellation over the union of persisted scheduled IDs and declared config IDs clears all reminders safely without clobbering other subsystems.

### Checking `cx.NotificationPermission` on launch

Querying `cx.NotificationPermission` inside `NewReminders` would populate `Permission()` immediately at startup. Rejected because NSGo's macOS notification center integration alters Dock badge behavior as soon as permission is queried, and issue `#1310` requires touching the OS notification permission API only on first `Schedule` or explicit `RequestPermission`.

## Consequences

- **Benefits**: Games get a zero-third-party-SDK re-engagement reminder system backed by deterministic YAML schemas, headless `nsgotest` verification, lazy OS permission prompts, quiet hours, and cross-restart foreground reconciliation. `liveops.Push` remains free to adopt NSGo's final remote push design cleanly once `nsgo-dev/nsgo#59` and `#1323` close.
- **Costs**: Because `CancelAll` closes tracked and declared IDs rather than calling `CloseNotifications()`, a reminder ID deleted from `reminders.yaml` in an app upgrade will only be cancelled automatically if it was tracked in `core.Storage` (or cleared individually). `Permission()` reports `NotificationsNotAsked` until the game either calls `Schedule` or `RequestPermission`.
