# Agent Note: Placing models into the editor's 3D viewport from the asset browser

Status: implemented

## Problem

In 3D a press on the editor's viewport only selected. The Place tool worked only in 2D, the asset browser listed only atlas frames, and an object's model could be named only by editing the scene file, so a 3D level could not be assembled from models in the editor (#893).

## Decision

- **What the browser offers** (`editor/models.go`): `Models` lists the built-in primitives in `sceneformat.MeshPrimitives` order, then `ProjectModels`: every `.gltf`/`.glb` file `ProjectFiles` lists plus every model target's `Out` in `game.yaml`, sorted and deduplicated, so a target shows before `game assets` has built it (`ModelEntry.Output`). The disk walk is cached by project path, `filesRev` and `assetsRev`, because the asset browser's memo runs on every editor revision; the targets are read from `Project` on each call, which is cheap and follows project edits.
- **Where a model lands**: `PlacementAt3D` casts `Camera3D.ScreenRay` into the 3D build and takes the nearest geometry hit, through the same loop picking uses (`rayGeometry3D`, which `pickGeometry3D` now calls, so hidden and locked objects are passed over in both); with no hit it intersects the horizontal plane at `PlaceHeight3D`. `PlaceSnap3D` rounds X and Z of a ground-plane point to `gridStep3D`, the spacing of the grid the viewport draws; a hit on geometry is not snapped, because that spacing grows with the camera's distance (16 units in the tests) and a snapped point would leave a small object's surface, sink into a wall or float over a slope. `PlaceModel3D` builds the model alone (`buildModel3D`, through the same `scene3DAssets` and cached `scenemodel.Assets` the scene's build uses), takes its bounds in object space, optionally turns +Y onto the normal with rotations about X and Z only (`alignUp3D`: `rotX = asin(nz)`, `rotZ = atan2(-nx, ny)` for the objects' Rx-then-Rz order), and lifts the origin along the normal by how far the turned bounds reach below it, so the geometry rests on the surface. The object goes through `PlaceObject`, which validates it, names its ID, raises a version 1 scene and makes it one undoable command.
- **Input paths**: `HandleViewport3DPress` places the `SelectedModel` when the tool is Place, before the gizmo check, so pressing beside the new object's gizmo still places. A drag uses `base/dragdrop`: `EditorView` wraps the main row in one `dragdrop.Area` and provides `dragAreaKey`, the model rows are `dragdrop.Source`s, and the viewport frame is a `dragdrop.Target` accepting `ModelEntry` in 3D; `AssetBrowserView` and `ViewportView` mounted on their own wrap themselves in an area so `Source`/`Target` never panic for want of one. A drag places whatever the active tool, since dragging a model onto the viewport says what to do. Files from another app arrive through `core.View.OnFileDrop`, are resolved with `core.FileFromURL`, must lie inside the project root after resolving symlinks, and are placed together in one `History.Group`.
- **Thumbnails** (`editor/model_thumbs.go`): each model is loaded and built on the UI goroutine the first time its thumbnail is drawn, since the editor's `Resolver` is not promised to be safe on others, through a `scenemodel.Assets` of its own rather than the 3D build's cache, so browsing keeps no model the scene does not use; and the build, which belongs to that job alone, is rendered by one worker goroutine with `scenemodel.Renderer` on a fresh `gpu.SoftwareRenderer` 64 pixels square, transparent background, framed by an `OrbitCamera3D` fitted to the bounds. Results are cached per entry until the project path or `assetsRev` changes; a stale generation's result is dropped. `modelThumbs` uses a multi-listener subscription map (`subscribe`/`notifyReady`), so the left asset browser (`modelListView`), the bottom 3D **MODELS** strip (`Viewport3DModelsStripView`), and the 3D inspector's **MODEL** card (`inspectorModel3DSections`) all redraw independently when any offscreen thumbnail finishes rendering without clobbering each other's callbacks or redrawing the 3D viewport.
- **3D Viewport bottom MODELS strip & inline agent prompt** (`editor/models_ui.go`, `editor/ui.go`): in 3D mode (when Assets drawer mode is off), `Viewport3DModelsStripView` renders the `Viewport3D.dc.html` **MODELS** strip (`"drag in"`) beneath the 3D viewport using only `SpecPalette` tokens. `StripModels` orders project glTF models before built-in primitives so the project's `.glb`/`.gltf` assets appear immediately without scrolling past primitives (while `Models` preserves primitives-first order for the left asset browser). Each card carries the `"Drag into the viewport to place <name>"` tooltip and is a `dragdrop.Source` inside the shared `dragdrop.Area`; **Or ask for one** stays pinned at the strip's right edge so it never scrolls out of sight and opens an inline Spec-styled prompt bar (`OpenModelAgentPrompt`, `SubmitViewport3DAgentPrompt`, `OnAskAgent3D`).
- **Inspector** (`editor/models.go`, `editor/models_ui.go`, `editor/inspector.go`): in 3D view, `inspectorModel3DSections` renders the `Viewport3D.dc.html` cards using `SpecPalette` tokens above Transform: **CHILDREN** (`ObjectChildrenSummary3D`) for groups, **MODEL** (`ObjectModelSummary3D`: offscreen thumbnail, path, triangle count and distinct material count derived from the cached 3D build's `scenemodel.Drawable` parts, plus the searchable `modelField` picker calling `SetObjectModel`), **MATERIAL** (`ObjectMaterialSummary3D`: material file basename plus roughness/metallic bars from the live Material Editor, material file, or built glTF material), **COLLIDER** (`ObjectColliderSummary3D`: human-readable shape and effective body kind such as `"Convex hull · static"`), and **Ask to add a component…** (`OpenComponentAgentPrompt`). `SetObjectModel` refuses a model that does not load and one on an object drawing a primitive (mirroring `SetObjectMesh`), clears `modelNode`/`modelMesh` with the model they belonged to, and restores all three and the scene version on undo.

## Alternatives considered

### Place the model's origin on the surface

Godot's default drops the origin where the ray hits. It is simpler and needs no bounds, but most models and every built-in primitive are centred on their origin, so a box or crate would sink half into the floor and every placement would need a gizmo drag; resting the bounds on the surface is what Unreal does and what a level author expects.

### Render thumbnails on the 3D viewport's GPU device or synchronously

The viewport's `gpu.View` device exists only while 3D is shown and belongs to its frame callback, so the browser in 2D would have no thumbnails. Rendering on the UI goroutine is simpler and deterministic but stalls the editor for a project with many models; the worker takes the rasterization off it and tests wait on it (`waitModelThumbnails`). Loading stays on the UI goroutine, so the first paint of a long list still reads each model once.

### Track the pointer to place file drops

`OnFileDrop` carries only URLs, and desktop platforms deliver no pointer moves to the app during an OS drag, so a tracked position would be stale. Dropped files land under the view's middle instead.

### Put "Or ask for one" inside the horizontal model strip scroll container

Putting the button after the last model card inside `ui.ScrollView` matches a fixed 6-card mockup, but in a real project with 6+ models plus 5 built-in primitives the button scrolls off the right edge and clicking it scrolls the project models out of view. Pinning **Or ask for one** as a right-aligned sibling outside the horizontal scroll container keeps both project models and the agent action visible at the same time.

## Consequences

- Placing loads the model on the UI goroutine the first time, through the same cache the scene's build uses, so the build that follows the placement loads nothing again.
- A file drop cannot choose its spot; this lifts once NSGo reports the drop's position (`core.View.OnFileDrop` in NSGo v0.3.0 passes only URLs; the gap is reported upstream).
- A dropped file is accepted only outside the folders `ProjectFiles` leaves out (`skippedProjectDir`: names starting with `.` or `_`, and `testdata`), so every model the editor places from a drop is one the asset browser and the inspector's Model field list.
- `SetObjectModel` raises only a version 1 scene, to version 2 (`modelsVersion`), the first with models; a version 2 file keeps its version and schema comment. `PlaceObject`, unchanged here, still raises to `sceneformat.CurrentVersion`.
- Pressing a model in the asset browser turns on the Place tool only in 3D, since the 2D Place tool adds atlas frames.
- A thumbnail reads its model a second time when the scene also draws it, the price of not keeping every listed model in the 3D build's cache.
- The software GPU renders each thumbnail with a renderer of its own, which costs a few milliseconds per model off the UI goroutine and isolates a failing model from the rest.
