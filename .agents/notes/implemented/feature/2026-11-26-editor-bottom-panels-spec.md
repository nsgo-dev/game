# Agent Note: Bottom editor panels aligned to the editor design Spec

Status: implemented

## Problem

The five bottom panels that remain in the main editor window — Animation (`animation_ui.go`), Data Table (`datatable_ui.go`), Localization (`localization_panel.go`), Search & References (`search_ui.go`), and Problems (`problems_ui.go`) — pre-dated `docs/design/editor/Spec.dc.html`. Each panel picked its own spacing (2/3/6 px), radii (3/4 px), type sizes, and NSGo default `ui.ColorsOf` surfaces, used plain ASCII characters (`^`, `v`, `x`, `×`) instead of Lucide icons, lacked tooltips and accessible names on several controls, and rendered clickable `core.View` elements without keyboard focus rings or `Space`/`Return` activation (notably animation keyframe markers, frame cells, event markers, search result rows, reference rows, and problem rows). Several controls also failed WCAG 2.2 contrast or layout rules (white text on accent fills, stacked vertical interpolation toggles, and `ui.NumberInput` / `ui.Select` overflowing fixed-width wrappers), and missing translations in the Localization panel relied primarily on a border tint rather than a non-color warning badge with an icon.

## Decision

Introduce a shared Spec-token primitive layer in `packages/game/editor/spec_panel_ui.go` and migrate all five bottom panels onto it, without touching the panels moving into Settings (Project, Input, Audio, Export):

### 1. Shared Spec bottom-panel primitives (`spec_panel_ui.go`)

All colors in the five panels come exclusively from the theme-aware `SpecPalette` returned by `ed.SpecPalette(cx)` (`Bg`, `Panel`, `Raised`, `Line`, `LineRaised`, `TextPrimary`, `TextSecondary`, `TextMuted`, `TextFaint`, `OnTextPrimary`, `Accent`, `Added`, `Changed`, `Problem()`, `Warning`, and appearance-aware hover/active overlays) so both Dark and Light Spec appearances stay WCAG-compliant automatically. Spacing uses only `4 / 8 / 12 / 16 / 24` px, radii use `6` (controls/rows), `8` (buttons/groups), and `12` (cards), headers use `44` px min height, and every interactive control maintains at least a `28 × 28` px hit area.

- **Real buttons and toggles (`specPanelButton`, `specPanelToggle`, `specPanelToggleGroup`, `specPanelRowButton`)**: built directly on NSGo's `base.Button`, `base.Toggle`, and horizontal `base.ToggleGroup` instead of clickable `core.View`s. Every control joins Tab or arrow-key roving focus, activates on `Space` and `Return`, carries an explicit accessible `Label`, shows a Spec tooltip (`specTooltipNode`) formatted with the effective command shortcut via `ed.EffectiveShortcut(...)` and `FormatShortcut`, and draws the 2 px `p.FocusRing(2)` / `p.FocusRing(-2)` outline (inset inside scroll views so the ring is never clipped).
- **Contrast-safe variants**: primary buttons use `p.OnTextPrimary` on `p.TextPrimary` (18.75:1 AAA in both Dark and Light), accent fills use `p.Accent.OnFill` on `p.Accent.Fg` (WCAG AA in both Dark and Light), and low-contrast white-on-accent combinations are never used.
- **Memoized reactive icons**: dynamic icons (`anim-play`, data table column sort icons, and localization's missing-count badge) read memoized state (`core.NewMemo`) rather than `rev` directly so 60 Hz animation playback or unrelated editor ticks cause zero icon remounts.
- **Input and picker width clamping (`specInputStyle`, `specNumberInputStyle`, `specSelectStyle`)**: override NSGo `ui.NumberInput`'s default 160 px width and `ui.Select`'s default 200 px width with `Width: core.Pct(100)` inside sized wrappers, and format animation time inputs to 2 decimals so steppers and text never clip or overlap neighbors.
- **Unified state cards (`specEmptyState`, `specLoadingState`, `specStatusBanner`, `specSeverityPill`)**: provide consistent Lucide icons (`15` px stroke, `currentColor`), spinners, and retry/dismiss/quick-add actions across all five panels.

### 2. Semantic severity and panel states

- **Problems (`problems.go`, `problems_ui.go`)**: error rows use `p.Problem()` with `lucide.TriangleAlert` and an `"Error"` pill; warning rows (`problemIsWarning`, matching `"warning:"` / `"warn:"` prefixes) use `p.Warning` (`Fg`, `Fill`, `Edge`) and a `"Warning"` pill + alert icon. Empty (`problems-empty`), loading (`problems-loading`), and error (`problems-error` with `problems-error-retry`) states are all explicit.
- **Localization (`localization_panel.go`)**: missing translations use `p.Warning.Fill` / `p.Warning.Edge` plus a top-anchored `lucide.TriangleAlert` + `"Missing translation"` badge (`l10n-missing-<loc>-<key>`) so plural cells never clip the cue and color is never the sole indicator. Adds `LocalizationError` / `ClearLocalizationError` and `LocalizationLoading` / `SetLocalizationLoading` for `l10n-error`, `l10n-loading`, and `l10n-empty` states.
- **Animation (`animation.go`, `animation_ui.go`)**: converts numeric key markers, sprite frame cells, and event markers from clickable `core.View`s to real `base.Button`s with `>= 28 × 28` hit targets, inset focus rings, and tooltips; places interpolation toggles (`Linear` / `Smooth` / `Step`) in a horizontal `base.ToggleGroup`; guards `durationOfSeconds`, `laneLeft`, and frame-span percentages against `NaN`/`Inf`/overflow; disables `anim-save` and `anim-scrub` during Play mode; adds `ClipLoading` / `SetClipLoading` (cleared on clip open/close and project/demo switch), `anim-empty`, `anim-loading`, and a Spec `anim-error` banner.
- **Data Table (`datatable.go`, `datatable_ui.go`)**: replaces ASCII sort/reorder/delete characters (`^`, `v`, `x`, `+`) with Lucide icons (`ArrowUp`/`ArrowDown`/`ArrowUpDown`, `ChevronUp`/`ChevronDown`, `Trash`, `Plus`, `Save`, `X`), includes filter presence in the grid structure memo so 0-row tables update between empty and filtered-empty states, adds `DataTableLoading` / `SetDataTableLoading` and `ClearDataTableError`, and adds empty (`datatable-empty` with Add Row / Clear Filter action), loading (`datatable-loading`), and dismissible error (`datatable-error`) states.
- **Search & References (`search.go`, `search_ui.go`)**: moves `Search` / `References` tabs into a horizontal `base.ToggleGroup` with Lucide icons, converts every result and reference row into a real `base.Button` with kind icons and inset focus rings, and adds `SearchLoading` / `SetSearchLoading` (cleared when searches/refreshes finish or on project/demo switch), `search-loading`, `search-empty` / `refs-empty`, and `search-error` with `search-error-retry`.

Related panel implementation notes: [Problems panel](2026-11-25-editor-problems-panel.md), [Data Table editor](2026-11-25-datatable-editor.md), [Project Search and References](2026-11-25-editor-project-search-and-references.md), and [Localization YAML editor](2026-11-25-l10n-yaml-editor.md).

## Alternatives considered

### Styling `ui.Button` and `ui.ToggleButton` in place without `base.Button` / `base.Toggle` helpers

Reusing `ui.Button` and `ui.ToggleButton` directly would avoid defining `specPanelButton` and `specPanelToggle`. Rejected because `ui.Button.Render` merges `FocusRing(cx, 2)` in `StyleFunc` (which tracks the OS palette accent instead of Spec's `#3B7BFF`), `ui.ButtonPrimary` and `ui.ToggleButton` render `#FFFFFF` on the accent fill (explicitly forbidden by the Spec contrast table at 3.84:1), and `ui.Button` only supports single-icon-plus-single-text faces rather than structured rows (severity pills, monospace paths, thumbnail canvases) that still need real button semantics. Building on `base.Button` and `base.Toggle` — the same primitives `ui.Button` wraps — preserves full NSGo accessibility, roving focus, and keyboard activation while enforcing Spec tokens everywhere.

### Adding a `Severity` field directly to `assetcheck.Problem`

Adding a public `Severity` enum to `packages/game/tooling/assetcheck.Problem` would make warning classification structured across CLI and editor. Rejected for this UI-focused issue because `assetcheck` is a separate public package with strict parity tests (`TestProblemsParityWithGameCheck`) and no CLI warning producers yet; classifying `"warning:"` / `"warn:"` prefixes in `problemIsWarning` keeps `assetcheck.Problem` backwards-compatible while enabling full Spec warning styling and testing today.

## Consequences

- **Benefits**: All five bottom panels share one theme-aware Spec token and spacing vocabulary across both Dark and Light appearances, pass WCAG 2.2 contrast ratios, expose Lucide icons and dynamic shortcut tooltips, support full Tab/arrow keyboard navigation with visible Spec focus rings, avoid 60 Hz icon remounts via memoized state, and present clear empty, loading, and error states. Visual inspection on macOS also eliminated pre-existing layout overlaps in the Animation panel (`NumberInput` steppers, `Select` width, and vertically stacked interpolation toggles).
- **Costs**: `spec_panel_ui.go` threads `SpecPalette` through its helper functions explicitly rather than inheriting `ui.ColorsOf(cx)` so contrast-verified button/badge fills and `p.FocusRing(...)` offsets remain strictly aligned with `Spec.dc.html` across both Dark and Light appearances.
- **Verification**: Covered by `packages/game/editor/bottom_panels_spec_test.go` (empty, loading, error, Light theme parity, memoized play/sort icons, loading resets, Play-mode controls, 0-row filter empty state, hit-area, role, Tab/arrow focus, and Space activation for all five panels), `packages/game/editor/problems_internal_test.go` (Problems loading, error, retry, warning-vs-error classification, and empty state), all existing panel and i18n tests, cross-target `go tool nsgo check` (host and `-target ios`), and before/after native macOS screenshots in `packages/game/editor/editorcmd/bottom_panels_screenshot_test.go`.
