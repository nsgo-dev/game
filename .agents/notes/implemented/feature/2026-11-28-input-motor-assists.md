# Agent Note: Player Motor Assists on Input Actions and game.yaml Assist Declarations

Status: implemented

## Problem

`a11y.Assist.HoldToToggle` was persisted in `save.AccessibilitySettings` (`nsgo-dev/game#1771`), but `pkg/input` had no motor accessibility pipeline: actions stayed pressed strictly while a physical binding was held, with no support for hold-to-toggle, press-once / hold-instead-of-mashing, slow-key minimum press durations, or bounce-key post-acceptance delays (`nsgo-dev/game#1777`). Games implementing these manually in update code duplicated per-action state, risked latching menu or pause actions, and diverged from `pkg/replay` recordings when evaluated outside the fixed step.

## Decision

Evaluate player-chosen motor assists (`input.Assists`) inside `Actions.Step()` using fixed-step timing, allow actions to opt in via `game.yaml` (`assist: {toggle, mash, mashRate}`), persist player choices in `save.Settings.InputAssists` alongside `Bindings`, and expose them through `a11y.Assist` and `gameui.SettingsMenu`'s Controls tab (extending [Unify Accessibility Preferences Across save, a11y, and gameui](../bug-fix/2026-11-28-a11y-settings-assist-sync.md) and [Ready Settings Menu in game/gameui](2026-11-24-gameui-settings-menu.md)).

### Fixed-step evaluation order and replay determinism (`pkg/input`)

- `Actions.Step()` runs a deterministic four-stage pipeline per action whenever `Assists` is non-zero or has active state:
  1. `MinPress` (slow keys): converts `time.Duration` to whole fixed steps via exact ceiling rational arithmetic (`ceil(d * rate / 1s)` at `SetStepRate`, defaulting to `DefaultStepRate = 60` Hz) so multiples like `100ms` at 60 Hz equal exact 6 steps without `16.666ms` truncation drift. Sub-step taps are rejected, and a release+repress between steps restarts the hold counter.
  2. `AcceptDelay` (bounce keys): starts a step cooldown upon each accepted press. Ongoing accepted holds continue uninterrupted; rejected presses during cooldown neither reset the cooldown nor fire mid-hold when cooldown expires. Running `AcceptDelay` before `Toggle` prevents tremor double-taps from cancelling a latched toggle.
  3. `Toggle`: flips latched state on each accepted rising edge for actions in `Assists.Toggle` that are eligible. `Actions.SetPaused(true)` / `Actions.ReleaseToggles()` releases latched toggles (firing `JustReleased` on the next step); `Actions.Reset()` clears all latched state immediately.
  4. `MashToHold`: while the action is held (physically or via `Toggle` latch for press-once mashing), emits 1-step pulses at the action's declared `MashRate` (`DefaultMashRate = 10` Hz when unset), always separated by at least one released step so `JustPressed` fires on every pulse and `replay.Recorder` / `replay.Player` reproduce identical `Pressed`, `JustPressed`, `JustReleased`, and `Axis` snapshots without format changes.
- `Player` forwards `SetAssists`, `Assists`, `SetActionAssist`, `ActionAssist`, `ToggleActive`, and `ReleaseToggles` to its own `Actions`; `Players` forwards `SetStepRate`, `SetPaused`, and `ReleaseToggles` across all slots.
- `Actions.Save` / `Actions.Load` persist optional `assists` in `storageVersion = 1` JSON (omitted when zero for backward compatibility).

### `game.yaml` action `assist` schema (`pkg/project`)

- `project.Action` adds `Assist *ActionAssist` (`yaml:"assist,omitempty,flow"`) with `Toggle bool`, `Mash bool`, and `MashRate float64` (`yaml:"mashRate,omitempty"`, validated finite non-negative and refused when `Mash` is false).
- `project.File.BindInput` registers `input.ActionAssist` for every action in `game.yaml` whenever any action declares `assist:`. Once any action on `Actions` has an `ActionAssist` declaration, `Toggle` and `MashToHold` operate in strict allowlist mode so undeclared actions (such as `pause` or menu navigation) can never be latched. When no declarations exist (pure-Go callers), actions explicitly named in `Assists.Toggle` / `Assists.MashToHold` remain active.
- `apps/website/public/schemas/game.v1.json` is regenerated by `go run ./tools/gameschema`.

### Settings persistence, `a11y.Assist` bridge, and Controls tab (`pkg/save`, `pkg/a11y`, `pkg/gameui`)

- `save.Settings` adds `InputAssists save.InputAssistSettings` (`json:"input_assists,omitzero"`, with `Toggle`, `MashToHold`, `MinPressMs`, `AcceptDelayMs`, clamped to `[0, 2000]` ms) and `save.SettingsTargets.ApplyInputAssists`. Keeping slice fields on `save.Settings` rather than `save.AccessibilitySettings` preserves `save.AccessibilitySettings` struct comparability (`==`) in `Stable` package `pkg/save`.
- `a11y.Assist` exposes `InputAssists`, `SetInputAssists`, `ApplyInputAssists`, `ApplyToActions`, and `ApplyToPlayers`. `ApplyToActions` merges `actions.ToggleableActions()` into `Assists.Toggle` whenever `HoldToToggle()` is true.
- `gameui.SettingsAction` adds `AllowToggle` and `AllowMash`. `SettingsMenu`'s Controls tab appends per-action Hold-to-Toggle / Hold-to-Mash toggles for actions opting in, plus `Min Press Time` and `Accept Delay` sliders (0–2000 ms in 50 ms steps) before `Reset Controls to Defaults`, preserving action button indices `[0..len(actions)-1]` and fitting within the 960×540 viewport without overlap.

## Alternatives considered

### Adding `Toggle []string` and `MashToHold []string` directly onto `save.AccessibilitySettings`

Co-locating all motor assist fields inside `save.AccessibilitySettings` would keep them in one JSON object. Rejected because `pkg/save` is a `Stable` package and `AccessibilitySettings` is currently a comparable value struct used with `==` in tests and callers; adding slice fields would break Go comparability. Placing `InputAssistSettings` as a sibling field on `save.Settings` (already non-comparable due to `Bindings` and `Custom`) with `omitzero` keeps `AccessibilitySettings` comparable and leaves default settings JSON unchanged.

### Evaluating `MinPress` and `AcceptDelay` against wall-clock `time.Now()`

Measuring hold durations with wall-clock time would avoid needing a step rate on `Actions`. Rejected because wall-clock timing breaks fixed-step determinism and causes `pkg/replay` recordings and tests to diverge across machines or frame hitches. Fixed-step evaluation at `Actions.StepRate()` (defaulting to 60 Hz) keeps replays exact.

### Requiring `SetActionAssist` even for pure-Go callers with no declarations

Enforcing allowlist mode unconditionally would prevent toggling any action unless `SetActionAssist` was also called. Rejected because pure-Go callers and unit tests binding a few actions with `a.SetAssists(input.Assists{Toggle: []string{"sprint"}})` expect direct configuration to work without extra boilerplate, while any game using `game.yaml` `assist:` or `SetActionAssist` automatically switches `Actions` into strict allowlist mode so menu actions are never latched.

## Consequences

- **Benefits**: Players can configure hold-to-toggle, press-once / hold-to-mash, slow-key minimum press time, and bounce-key accept delay globally or per player, persist them through `save.DefaultSettingsStore` or `Actions.Save`, preview and edit them in `gameui.SettingsMenu`'s Controls tab, and record/replay gameplay deterministically.
- **Costs**: `pkg/a11y` (`Experimental`) now imports `pkg/input` (`Stable`), `game.v1.json` grows by the optional `ActionAssist` definition, and `SettingsMenu`'s Controls tab adds two timing sliders plus optional per-action assist toggles.
- **Trade-off**: Games running at a fixed rate other than 60 Hz must call `actions.SetStepRate(loop.StepRate())` (or `players.SetStepRate(...)`) so millisecond assist thresholds convert using the actual step rate.
