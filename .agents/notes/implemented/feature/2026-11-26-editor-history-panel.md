# Agent Note: Editor unified History timeline panel, preview, and non-destructive restore

Status: implemented

## Problem

`editor.History` previously stored only an opaque `[]Command` slice with a cursor and a `Label()` string. Manual edits, kept agent turns, external reloads, and save points had no author metadata, old-to-new detail, change/kept counts, touched file list, or timestamps. Authors could only step backward destructively via linear `Undo`, had no way to preview an earlier state of the scene without mutating the open document or moving the undo cursor, and connected agents could not inspect recent edit history through `editormcp`.

## Decision

Extend `editor.History` and `editor.Editor` with a unified session timeline (`history.go`, `history_timeline.go`, `history_ui.go`) and expose read-only history inspection over MCP (`editormcp/history.go`), building on the MCP server contract in [editor-mcp-server](../../implemented/architecture/2026-11-25-editor-mcp-server.md):

- **Immutable per-entry snapshots on `History`**: every recorded command (`Execute`, `Group`, `commitPreview`) and every saved-point marker (`RecordSaved`) appends a `historyRecord` holding a `HistoryEntry` (stable monotonic `ID`, `Kind`, `Author`, `Summary`, `Detail`, `Files`, `Timestamp` from an injectable clock, `ChangeCount`, `KeptCount`, `CommandIndex`, `Undone`, `RestoredFromID`) plus a deterministic YAML snapshot (`sceneYAML`, `projectYAML`, and any extra touched project files). When linear `Undo` followed by a new edit truncates the redo tail of `commands`, superseded timeline records retain their snapshots with `Undone: true` so no recorded state is lost during the session.
- **Rich metadata without breaking `Command.Label()`**: commands optionally implement `historyMetaCommand` (implemented on core object commands in `state.go`, `replaceSceneCmd` in `scenefile.go`, and `restoreHistoryCmd` in `history_timeline.go`) to emit concise Spec-formatted summaries and `old → new` details (`"moved Knight"` / `"x 416 → 452"`), while `Command.Label()` and `History.UndoLabel()` remain unchanged for existing callers and tests.
- **First-class agent turns and automatic MCP attribution**: `Editor.RecordAgentTurn` groups scene, project, and extra touched disk files into one undoable step (`agentFilesCmd` captures disk deltas alongside scene/project commands) with `HistoryAuthorAgent`, request title, change/kept counts, and pre/post file snapshots. `editormcp.Server.asAgent` brackets tool execution with `EnterAgentContext` / `LeaveAgentContext`, and `KeepTileReview` / `KeepCutsceneReview` stamp their kept commits as `HistoryAuthorAgent`.
- **Zero-mutation point-in-time preview**: `PreviewHistoryEntry` parses and builds the entry's `sceneYAML` into `Editor.historyPanel.preview` (`doc` + `scene`) without mutating `Editor.Doc`, `Editor.Built`, or `History.cursor`. `ActiveScene()` and `scene3D()` serve the preview scene while active; `DrawViewport` skips editing overlays; viewport press/drag entry points refuse edits; and `Esc`, **Back**, **Now**, `Play`, or switching tabs clears preview cleanly.
- **Non-destructive multi-file Restore**: `RestoreHistoryEntry` collects the target entry's snapshot plus the earliest pre-change `beforeFiles` of every extra file touched after the target, validates the target YAML, and executes one `restoreHistoryCmd` (`fallibleCommand`) on `History`. Later entries stay in the timeline and can still be previewed or restored, and a single `Undo` returns the scene, project, and extra files to the state immediately before Restore.
- **UI and MCP surface**: `CmdHistoryPanel` (`mod+y`, View > History, and a compact 28×28 `toolbar-history` icon button with tooltip `"History · ⌘Y"`) toggles `HistoryPanelView` in the right rail using exclusively `SpecPalette` tokens (`AskInPlace.dc.html` / `Checkpoints.dc.html` / `Spec.dc.html`), with **Now** (`unsaved`/`saved`), day headers (`TODAY` / `YESTERDAY` / date), **All** / **You** / **Agent** filter tabs, and a floating `"Previewing … · editing is off"` viewport banner. `editormcp` adds read-only `history_list` (`ActionRead`) supporting `author` and `limit` filters.

## Alternatives considered

- **Replaying `Command.Undo()` / `Command.Do()` on `Editor.Doc` to preview an earlier step**: this would avoid storing per-entry YAML snapshots in memory. Rejected because replaying commands directly mutates `Editor.Doc`, `History.cursor`, selection, and disk-backed commands (`MoveFile`, `cutsceneCommitCmd`), violating the requirement that preview never mutates the live document or undo cursor and risking corrupting state if preview is interrupted.
- **Implementing Restore by moving `History.cursor` backward**: moving the undo cursor is simpler and needs no new command type. Rejected because it would discard or overwrite later steps as soon as the author makes another edit, breaking the requirement that later steps stay restorable and that one `Undo` returns immediately to the latest state.
- **Persisting checkpoints to `.nsgo/checkpoints` on disk in this change**: `Checkpoints.dc.html` shows disk-backed checkpoints across sessions. Rejected as out of scope for #1017, which explicitly leaves cross-session checkpoints to their own issue while ensuring this panel's timeline structure can display them later.

## Consequences

- **Benefits**: authors and agents share one inspectable timeline covering manual edits, multi-file agent turns, Git reloads, and saves; preview is guaranteed read-only and non-mutating; Restore is atomic across touched files and reversible in one Undo; existing `UndoLabel()` and toolbar layout invariants remain intact.
- **Costs**: each recorded timeline step retains serialized scene/project YAML (and snapshots of extra files touched by agent turns) in memory for the lifetime of the open tab's `History` until `History.Clear()` or tab close; very long sessions with large scenes will use more RAM than command-only deltas until a future compaction or disk-checkpoint issue offloads older snapshots.
