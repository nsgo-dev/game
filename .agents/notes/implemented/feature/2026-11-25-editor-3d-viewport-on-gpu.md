# Agent Note: The editor's 3D viewport draws the scene with render3d on a GPU view

Status: implemented

## Problem

The editor's 3D viewport drew every object as a wireframe box sized by its sprite frame. Once scene files could name built-in primitives and glTF models (scenemodel, #889), a 3D author still could not see the models, materials or lighting being placed in the editor, and a press picked boxes, not geometry: a press beside a sphere selected it, and a model with no sprite was a 16-unit marker.

## Decision

- **One 3D build per look, posed in place** (`editor/scene3d.go`): the editor keeps the open scene built with `scenemodel.Build` (`Editor.Scene3D`) in a `scene3d.Scene`. `Rebuild` marks it stale, except during a 3D gizmo drag; the next draw or pick compares a hash of what decides the look (`lookKey3D`: layers, each object's place in the tree, `mesh`, `model`, `modelNode`, `modelMesh`, `material`, `scene`, and overrides as JSON) and builds again only when it changed, the project or its assets changed, or the last build failed. The build generation only grows, closing the scene included, so a renderer never takes a new build for the one it uploaded. Every draw and pick then copies each object's transform, posed by the open clip (`posed3D`) or the playing game (which mutates `e.Doc`), onto its node with `SetLocal` when it differs, sets hidden objects' nodes invisible and screen-space layers' nodes invisible. A gizmo drag, an undo of a move, a clip's playhead and Play therefore rebuild no mesh and upload nothing; only a change of look rebuilds.
- **Resolvers**: models, material files and images load through the editor's `Resolver` when it implements the matching interface, and from `scenemodel.NewAssets(os.DirFS(projectDir))` otherwise (`scene3DAssets`). The project assets are recreated when the project or `assetsRev` changes: opening a project, moving files, installing or removing packs, reloading built assets (`ReloadAssets`) and rescanning from disk (`RefreshSearch`) bump it, but saving a scene, clip, data table or localization table does not, since the editor never writes a model, material file or image, so pressing mod+s does not re-read and re-upload every model. A scene that instances or inherits files is resolved first with the Resolver as its `SceneResolver`.
- **Drawing** (`editor/viewport3d_gpu.go`): in 3D mode `ViewportView` wraps the canvas in `gpu.View` (depth `Depth24Plus`). `viewport3DRenderer` holds a `scenemodel.Renderer` for the current build generation, a skybox pipeline and a gradient sky cubemap; each frame it clears to the scene's background, draws the sky (no depth writes) and then the geometry. It records a frame only when the editor's revision, the surface size or the build generation changed, so an idle editor submits no GPU work and the last presented image stays; a frame that failed (an upload error, lights the renderer refuses) is not tried again until one of them changes, so a persistent error does not re-upload the build every display frame. The canvas over it becomes an overlay while `Viewport3DOnGPU` is true: no background, no boxes for objects whose geometry the GPU draws, the selected object's box as its outline, and in Wireframe shading the triangle edges projected on the canvas, each edge once by its two end positions, so a mesh that splits its corners per face strokes a shared edge once. Lights are `Editor.Lights3D`, set with `SetLights3D` so the viewport redraws, or `DefaultLights3D` under the sky; scene files hold no lights.
- **Shading**: `Shading3D` (Lit, Unlit, Wireframe) is a view setting with commands, a View submenu and a toolbar group. Unlit is a new `scenemodel.Renderer.SetShading(ShadingUnlit)`, whose pipelines compile a separate shader module (`unlitShaderWGSL`) on first use.
- **Picking**: every object whose node draws geometry gets a `scene3d.MeshCollider` of its triangles at build time. `Pick3D` raycasts the build with the same ray the gizmo uses, skips hits whose owner (the nearest object the open scene holds, for instanced geometry) or an ancestor is hidden or locked, and falls back to the box test for objects without geometry only where no geometry is hit: those boxes are 16 units whatever the scene's scale, so in a meter-scale scene an empty object's box holds the camera and the whole level and would win every press if the two were compared by distance. `ObjectCorners3D` and `ObjectAABB3D` return the geometry's bounds in the object's space under its transform.
- **Fallback**: where `cx.Env().SupportsGPU()` is false, `gpu.View` renders its children in a plain view and reports `ErrUnsupported`; the editor clears `Viewport3DOnGPU`, and the canvas draws the whole wireframe view, now with geometry-sized boxes and geometry picking, which need no GPU.

## Alternatives considered

- **Rebuild the 3D scene on every `Rebuild`**: simplest, and always correct. Rejected because a gizmo drag calls `Rebuild` every move, and building re-reads materials, re-decodes glTF textures and forces a fresh GPU upload each frame, which the issue rules out.
- **Track a dirty flag per edit command instead of hashing the look**: exact. Rejected because every edit path (inspector, scene tree, undo, open, play, plugins) would have to say whether it changed the look; the hash needs no cooperation and costs one walk of the objects per real edit, not per frame.
- **Render the wireframe overlay on the GPU with a line-list pipeline**: depth-tested lines. Rejected for now because NSGo v0.3.0's software renderer draws every topology as a triangle list (`internal/driver/gpu_software.go:1324`), so headless tests could not check it; the canvas overlay draws the same edges on every target.
- **Unlit through a second fragment entry point in `ShaderWGSL`**: one module. Rejected because NSGo v0.3.0's software renderer runs a module's first fragment entry whatever the pipeline names (`gpu/device.go:1599` passes the whole module's IR; `internal/driver/gpu_software.go:984` keeps its `FragmentFunc`), so the unlit pipeline drew lit.
- **Pick the nearer of a geometry hit and a marker box**: one distance test for everything. Rejected because the fixed marker boxes swallow meter-scale scenes; the cost is that a marker in front of geometry is selected from the scene tree, not by a press.
- **Render every display frame**: what `gpu.View` is built for. Rejected because the editor is idle most of the time and the software GPU in nsgotest made every frame of a mounted 3D test cost seconds; frames now render only when what they show changed.

## Consequences

- Benefits: 3D authors see models, textures and lighting while placing them, and a press selects the geometry under it; drags stay incremental; a target without a GPU keeps a working, better-sized wireframe view.
- Costs: the editor imports `scenemodel` and `render3d`, and keeps a CPU copy of each mesh's triangles for picking. The canvas overlays (grid, outline, wireframe edges) are not depth-tested against the geometry. The wireframe overlay stops after `maxWireframeEdges3D` edges a frame. The editor's 2D build (`sceneformat.Build`), which Play and the clip preview use, still needs a Resolver that serves material files; an editor whose Resolver does not cannot play a 3D scene that names materials, as before.

## Testing

- `packages/game/editor/viewport3d_gpu_internal_test.go`: renders the scenemodel courtyard through `viewport3DRenderer` on `gpu.NewSoftwareRenderer` and compares `testdata/golden/viewport3d.png`, with pixel checks for the crate's texture, the sky, unlit shading and `Lights3D`; a gizmo drag test checks each frame draws the moved crate without a new build or upload, that committing and undoing do not rebuild, and that changing a mesh does.
- `packages/game/editor/viewport3d_gpu_test.go`: geometry picking against a sphere's bounds corner, locked objects and instanced geometry; a mounted nsgotest editor whose GPU view shows the scene and whose canvas draws only overlays, the shading toolbar and commands; `nsgotest.NoGPU()` keeping the wireframe view with geometry boxes and picking; a build error shown in the viewport; the clip pose and a playing game moving the built nodes.
- `packages/game/scenemodel/renderer_test.go`: unlit shading draws the sphere one flat color and keeps the crate's texture; `SetShading` refuses unknown values and a closed renderer.
